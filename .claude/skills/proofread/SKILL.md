# 원고 장 파일 교정

공통 문체·표기·금지 표현과 교정 절차는 **korean-tech-writing 스킬**을 따르고,
AsciiDoc 공통 마크업은 **korean-asciidoc 스킬**을 따른다.
이 문서는 그 위에 얹는 이 책만의 규칙이고, 충돌하면 이 문서와 `book/CLAUDE.md`가 우선한다.

## 1차 기준

`book/CLAUDE.md`의 "문체 가이드", "금지·주의 표현", "AsciiDoc 표기 규약"이 이 책의 교정 기준이다.
컨텍스트에 없으면 먼저 Read로 읽는다. 아래 셋은 공통 스킬과 다르므로 특히 주의한다.

* **어조**: '~다'체. 유일한 예외는 `preface.adoc`이다(저자 서문과 "이 책을 읽는 법" 절까지 '~습니다'체,
  맨 끝 "저자 소개" 절은 다시 '~다'체). 본문 원고에서 '~습니다'체를 발견하면 고친다.
* **AsciiDoc은 downdoc 부분집합만 쓴다**: 굵게는 `*별표 한 겹*`(마크다운식 `**두 겹**`은 빌드가 에러로 잡는다),
  중첩 목록 금지, 패스스루 `+…+`·문서 속성 정의 금지, 각주는 `footnote:[본문]` 매크로.
  korean-asciidoc 스킬의 unconstrained 이중 별표 규칙은 이 책에 적용하지 않는다
  (백틱이 든 인라인 코드를 이중 백틱으로 감싸는 규칙은 그대로 쓴다).
* **원고는 `cat`이 아니라 Read 도구로 읽는다.** 훅이 주석과 `tag::` 마커를 걸러 낸다.
  긴 파일은 나눠서라도 처음부터 끝까지 읽는다.

## 이 책만의 점검 항목

* **장 번호는 본문에 직접 쓰지 않는다.** 다른 장 참조는 `{ch-파일명}` 토큰이다.
  본문에서 날 숫자 장 참조("15장에서")를 발견하면 토큰으로 바꾼다.
  예외 셋(코드 블록 안 생략 주석, "N부" 참조, 카드 수 세기 "카드 8장")은 그대로 둔다.
* **용어 상자 소유권**: 한 용어의 상자는 책 전체에서 한 장만 갖는다(`book/CLAUDE.md`의 배정표).
  다른 장에 중복 상자가 보이면 고치지 말고 보고한다. 상자 제목은 `[용어 풀이] 이름(영문)` 형식이다.
* **비개발자 독자**: 전문용어로만 굴러가는 문장은 일상어 풀이가 먼저 오는지,
  코드 블록 앞에 "이 코드가 하는 일" 한두 문장이 있는지 본다.
* **장 제목(첫 줄 `=`)을 고치면** `book/book.config.mjs`의 toc 제목도 함께 고친다
  (사이드바·PDF 차례·`{ch-…}` 라벨이 전부 toc에서 파생된다).
  절 제목은 다른 원고가 참조하는 곳이 있는지 grep으로 확인한다.
* **문법 입문 장(2부의 HTML·CSS·Go 장)의 예제는 저장소에 없는 직접 작성 코드다.**
  이 코드를 고치는 수정은 실제로 컴파일·실행해 확인해야 하고, 출력 예시 블록도 실행 결과와 맞춘다.
* **본문의 인라인 코드 언급(함수·필드·경로 이름)은 빌드가 검사하지 않는다.**
  실제 저장소 코드와 grep으로 대조한다(`include::`로 인용한 코드는 빌드가 대조해 준다).

## 고치지 않는 것

공통 스킬의 목록에 더해, 이 책에만 있는 것들이다.

* `include::`로 인용되는 코드(원본이 저장소 코드라 원고에 없다). 인용 경로·태그 이름도 건드리지 않는다.
* `++++` 패스스루 블록의 HTML 구조(화면 캡처 배치). `fc-caption`의 문구는 교정 대상.
* `{ch-…}` 토큰을 날 숫자로 풀지 않는다.

## 표기 일관성 grep 대조

원고 전체는 아래 경로다.

```bash
cd book
grep -c "표기A" intro.adoc preface.adoc part*/*.adoc appendix/*.adoc   # 파일별 건수
grep -rn "표기A\|표기B" intro.adoc preface.adoc part*/*.adoc appendix/*.adoc | head -20
```

책 전체가 혼용이면 `book/CLAUDE.md` 지침·국어 규범에 맞는 쪽으로 **해당 파일 안에서만** 통일하고,
다른 장에도 혼용이 남아 있다는 사실을 보고한다
(`book/CLAUDE.md`에 정해진 예: "포맷터"가 아니라 "포매터", "도구 사슬"이 아니라 "툴체인").

## 검증

1. 고친 패턴이 남아 있지 않은지 이번에 고친 패턴들로 grep을 다시 돌린다.
2. 책 빌드를 돌린다. 깨진 링크, `{ch-…}` 토큰 오류, AsciiDoc 부분집합 위반을 여기서 잡는다.

    ```bash
    cd book && npm run build
    ```

3. 장 제목이나 차례가 바뀌었으면 `npm run pdf`도 돌린다.
4. 커밋은 사용자가 요청할 때만 한다.

## 보고 형식

korean-tech-writing 스킬의 보고 형식을 따르되, "저자 확인 필요" 항목에 아래 둘을 더한다.

* 문법 입문 장 예제의 실행 재확인 필요 여부
* 용어 상자 소유권 위반
