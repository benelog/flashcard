= database/sql 첫걸음: Go로 SQLite에 저장하고 꺼낸다

앱의 서버 옆에는 sqlite3 프롬프트 앞에 앉아 문장을 쳐 줄 사람이 없다.
사용자가 덱을 만들 때마다 insert 문장을 데이터베이스에 보내는 것은 Go 코드가 할 일이다.
이 장에서는 {ch-go-hello}·{ch-go-types}의 Go와 {ch-database-basics}의 SQL을 잇는 코드를 읽는다.

이 장부터 2부의 남은 세 장은 저장소의 `flashcard-basic/`에 있는 최소 플래시카드 앱을 읽는다.
완성본(`flashcard-advanced/`)에서 배포·인증·간격 반복을 걷어 내고 웹 앱의 기본 구조만 남긴 앱이다.
테이블은 `decks`와 `cards` 둘뿐이고, 로그인이 없으며, 데이터는 현재 디렉터리의 `flashcard.db` 파일 하나에 저장된다.
그 폴더에서 `go run .`을 실행하면 `http://localhost:8080`에서 열린다.
이 장이 맡는 것은 데이터 층, 파일로는 `flashcard-basic/store.go` 하나다.

== database/sql과 드라이버

Go 표준 라이브러리의 `database/sql` 패키지는 SQL 데이터베이스 일반을 다루는 창구라, 연결을 열고 문장을 실행하고 결과를 받는 방법이 어느 데이터베이스든 같다.
각 데이터베이스와 대화하는 세부는 드라이버({ch-database-basics})가 맡는다.
완성본이 로컬에서는 SQLite로, 운영에서는 PostgreSQL로 도는 것도 이 구조 덕분이다({ch-supabase-db}).

flashcard-basic이 쓰는 SQLite 드라이버는 modernc.org/sqlite다.
C 언어로 만든 SQLite를 Go로 통째로 옮긴 순수 Go 구현이라, C 컴파일러 없이 `go build` 하나로 빌드가 끝난다.
널리 쓰이는 또 다른 드라이버 mattn/go-sqlite3는 C로 된 원본을 cgo(Go 코드와 C 코드를 함께 컴파일하는 장치)로 빌드하므로, `CGO_ENABLED=1` 설정과 C 컴파일러 gcc가 있어야 하고 윈도우에서는 TDM-GCC 같은 툴체인을 따로 설치해야 한다footnote:[go-sqlite3 README의 빌드 요구 사항 https://github.com/mattn/go-sqlite3[mattn/go-sqlite3]].

드라이버를 들이는 방법이 조금 별나다.
`flashcard-basic/store.go`의 임포트 목록에서 발췌한 두 줄이다.

[source,go]
----
	"database/sql"

	_ "modernc.org/sqlite"
----

임포트 경로 앞의 밑줄 `_`는 "이 패키지의 이름을 코드에서 쓰지는 않지만, 불러오기는 하라"는 표기다({ch-go-hello}에서 쓰지 않을 반환값을 버린 그 밑줄이다).
Go는 패키지를 불러오는 순간 그 패키지의 초기화 코드를 실행하고, 드라이버는 그 초기화에서 "나는 sqlite라는 이름의 드라이버다"라고 `database/sql`에 자신을 등록한다.
이 등록이 목적인 임포트이고, 등록된 이름은 잠시 뒤 `sql.Open`의 첫 인자로 다시 나온다.

== 연결 열기와 스키마 적용

테이블의 틀은 {ch-database-basics}에서 읽은 `flashcard-basic/schema.sql`에 있다.
`create table if not exists`로 적혀 있어 몇 번을 다시 실행해도 안전한데, 곧 볼 코드가 이 성질을 이용한다.
이 파일을 Go 코드로 가져오는 일은 `store.go`의 다음 두 줄이 한다.

[source,go]
----
//go:embed schema.sql
var schemaSQL string
----

`//go:embed`는 주석처럼 생겼지만 컴파일러가 읽는 지시다.
빌드할 때 `schema.sql`의 내용을 이 변수에 담아 실행 파일 안에 품으므로, 실행 파일을 어디로 가져가도 스키마 파일을 따로 챙길 필요가 없다(이 장치는 {ch-html-template}에서 자세히 다룬다).

연결을 열고 스키마를 적용하는 코드다.

[source,go]
----
include::../../flashcard-basic/store.go[tag=open]
----

`Store`는 데이터베이스 연결 하나를 감싼 구조체이고, 앞으로 볼 함수들은 모두 이 구조체의 메서드({ch-go-types})다.
`sql.Open`의 첫 인자 `"sqlite"`가 드라이버가 등록해 둔 이름이고, 둘째 인자가 열 파일의 경로다.
경로 뒤에 `?`로 붙인 `_pragma=foreign_keys(1)`은 연결 옵션이다.
SQLite는 옛 버전과의 호환 때문에 외래 키 검사가 꺼진 채로 출발하므로, 연결할 때마다 켜 줘야 `references` 선언이 실제로 일한다.

`db.SetMaxOpenConns(1)`은 연결을 한 개만 열게 한다.
`database/sql`은 요청이 동시에 여럿 들어오면 연결도 여러 개 여는데, 파일 하나에 저장하는 SQLite는 한 연결이 쓰는 동안 다른 연결이 쓰려 하면 "database is locked" 오류로 거절한다.
연결을 하나로 묶어 두면 요청들이 줄을 서서 차례로 쓰므로 이 오류가 나지 않는다.

연결이 열리면 `db.Exec(schemaSQL)`로 스키마 파일을 통째로 실행한다.
새 파일이면 테이블이 생기고, 이미 있으면 조용히 넘어간다.
그래서 이 앱에는 데이터베이스 설치도 준비 절차도 없이, 서버를 켜면 파일과 테이블이 함께 준비된다.
{ch-first-run}에서 완성본을 처음 실행했을 때 `flashcard.db`가 저절로 생긴 것도 같은 방식이다.

== 한 행 꺼내기: QueryRow와 Scan

id로 덱 하나를 찾아오는 함수다.

[source,go]
----
include::../../flashcard-basic/store.go[tag=get-deck]
----

`QueryRow`는 결과가 한 행뿐인 조회에 쓰고, 돌아온 행을 Go 값으로 옮기는 것이 `Scan`이다.
`&d.ID`처럼 필드의 포인터({ch-go-types})를 넘기면 select 문장의 열 순서대로 값이 채워진다.
select의 열 순서와 `Scan`에 넘긴 순서가 어긋나면 값이 엉뚱한 필드로 들어가므로, 둘은 늘 나란히 놓고 맞춘다.

이 함수의 절반은 "없을 때"를 다룬다.
조건에 맞는 행이 없으면 `database/sql`은 `sql.ErrNoRows` 에러를 내놓는데, 이 함수는 그것을 이 앱의 에러인 `ErrNotFound`로 바꿔 돌려준다.
`errors.Is`는 돌아온 에러가 바로 그 에러인지 확인하는 표준 라이브러리 함수이고, 그 경우 빈 `Deck` 값(제로값)과 함께 `ErrNotFound`를 내보낸다.
`ErrNotFound`는 `store.go` 첫머리에 선언해 둔 값이다.

[source,go]
----
var ErrNotFound = errors.New("not found")
----

바꿔 돌려주는 이유는 부르는 쪽에 있다.
화면을 만드는 쪽은 "찾는 덱이 없다"는 사실만 알면 404(서버가 "찾는 것이 없다"는 뜻으로 돌려주는 응답 번호, {ch-gin-hello})를 만들 수 있다.
`sql.ErrNoRows`를 그대로 내보내면 store를 부르는 모든 코드가 `database/sql`의 사정까지 알아야 한다.
이렇게 약속된 상황을 나타내려고 미리 만들어 두고 `errors.Is`로 알아보는 에러 값을 센티널 에러라 부른다({ch-core-logic}).

[source,go]
----
include::../../flashcard-basic/store.go[tag=list-cards]
----

결과가 여러 행이면 `Query`를 쓴다.
돌아오는 `rows`는 결과 전체를 담은 목록이 아니라, 책을 손가락으로 짚으며 읽듯 결과를 한 행씩 짚어 가는 읽기 창이다.
`rows.Next()`는 다음 행으로 넘어가며 행이 남아 있으면 `true`를 돌려주므로, 조건 반복 `for`에 끼우면 "행이 있는 동안 반복"이 된다.
회차마다 `Scan`으로 행 하나를 `Card`에 옮기고 `append`({ch-go-types})로 슬라이스에 쌓는다.

`defer rows.Close()`의 `defer`는 새 문법으로, "이 일을 지금 하지 말고 이 함수가 끝날 때 하라"는 예약이다.
읽기 창은 다 쓰면 닫아 자원을 돌려줘야 하는데, 함수를 빠져나가는 길은 정상 반환과 중간의 `return`들로 여러 갈래다.
여는 데 성공한 직후 닫는 일을 `defer`로 예약해 두면 어느 길로 나가든 빠짐없이 닫힌다.

마지막 줄의 `rows.Err()`도 빠뜨리기 쉽다.
반복 도중 읽기에 문제가 생기면 `rows.Next()`는 에러를 돌려줄 자리가 없어 그냥 `false`로 반복을 끝내므로, 끝까지 잘 읽었는지를 따로 물어야 한다.

덱 목록을 가져오는 `ListDecks`도 테이블과 열만 다를 뿐 같은 모양이다.
여러 행을 읽는 `database/sql` 코드는 어디서나 `Query`, `defer rows.Close()`, `rows.Next()` 반복, `Scan`, `rows.Err()`의 다섯 박자로 돈다.

== 직접 해 보기

`flashcard-basic/store.go`를 고쳐 보자.
고친 뒤 그 폴더에서 `go test ./...`를 돌리면 기존 함수를 망가뜨리지 않았는지 기계가 확인해 준다.

. 카드 한 장을 번호로 찾아 돌려주는 `GetCard` 함수를 더한다. `GetDeck`이 본보기이고, 찾지 못했을 때 `ErrNotFound`를 돌려주는 부분까지 따라 하면 된다.
. 그 함수를 확인하는 테스트를 `store_test.go`에 더한다. 카드를 만들고, 방금 만든 번호로 찾고, 없는 번호로도 찾아 `ErrNotFound`가 나오는지까지 보면 충분하다.
. `ListCards`의 자리표시자 `?`를 없애고 SQL 문장에 값을 직접 이어 붙이도록 고쳐 본다. 카드 내용에 작은따옴표가 들어가면 어떤 일이 벌어지는지 확인한 뒤 원래대로 되돌린다. 자리표시자를 고집하는 이유를 직접 확인하는 실험이다.

== 에이전트 활용 아이디어

데이터베이스 코드를 맡길 때는 기존 함수를 본보기로 지목한다.
"카드의 앞뒷면을 고치는 UpdateCard를 store.go에 추가하되, DeleteCard처럼 RowsAffected를 확인해 ErrNotFound를 돌려주라. store_test.go에 검증도 더하고 `go test ./...`가 통과하는 것까지 확인해 달라"처럼 따를 모양과 검증을 함께 지시하면, 이 파일의 규칙이 새 코드에도 이어지고 결과를 실행으로 받는다.

"SQL에 값을 이어 붙이지 말고 자리표시자를 쓰라", "rows를 열면 `defer rows.Close()`와 마지막 `rows.Err()` 확인을 빠뜨리지 말라"는 `AGENTS.md`에 적어 둘 만하다.
에이전트가 쓴 코드를 리뷰할 때도 이 목록이 점검표가 된다.

에이전트가 만든 함수를 실행한 뒤 "sqlite3로 flashcard.db를 열어 방금 넣은 행을 select로 보여 달라"고 시키면, Go 코드가 실제로 남긴 데이터를 눈으로 대조할 수 있다.

== 정리

첫째, `database/sql`은 어느 SQL 데이터베이스든 같은 방법으로 다루는 표준 창구이고, 세부는 `_ "modernc.org/sqlite"`처럼 밑줄 임포트로 등록한 드라이버가 맡는다.

둘째, 연결은 `sql.Open`으로 열고, `//go:embed`로 실행 파일에 품은 `schema.sql`을 `Exec`으로 실행해 테이블을 준비한다.

셋째, 넣기·고치기·지우기는 `Exec`으로 실행한다.
값은 자리표시자 `?`로 넘기고, 새 행의 번호는 `LastInsertId`로, 영향을 받은 행 수는 `RowsAffected`로 받는다.

넷째, 한 행은 `QueryRow`와 `Scan`으로 구조체에 옮기고, 여러 행은 `Query`, `defer rows.Close()`, `rows.Next()` 반복, `Scan`, `rows.Err()`의 다섯 박자로 읽는다.

다섯째, `sql.ErrNoRows` 같은 라이브러리의 에러는 store 안에서 `ErrNotFound`로 바꿔, 부르는 쪽이 `database/sql`을 몰라도 "없다"는 상황을 다루게 한다.

다음 {ch-gin-hello}에서는 이 함수들이 웹 서버에 연결되어, 브라우저의 요청에 store에서 꺼낸 덱과 카드가 HTML 화면으로 돌아가는 왕복을 읽는다.
