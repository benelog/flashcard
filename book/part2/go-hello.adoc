= Go 첫걸음: Hello, World로 배우는 기본 문법

{ch-html-hello}과 {ch-css-hello}에서 화면의 언어를 익혔다.
이번에는 그 화면 뒤에서 데이터를 다루고 요청에 답하는 서버의 언어, Go(고) 차례다.
Go를 고른 이유는 {ch-tech-choices}에서 정리했으니, 여기서는 언어 자체를 익힌다.

그런데 프로그래밍이 처음이라면 이 저장소의 코드를 곧바로 펼치는 것은 좋은 출발이 아니다.
파일 하나만 열어도 `func`, `:=`, `*Config`, `err != nil` 같은 낯선 기호가 한꺼번에 쏟아지고, 거기에 암기 카드 앱이라는 주제까지 얹히면 무엇이 언어의 문법이고 무엇이 이 앱에서만 쓰는 이름인지 구별하기 어렵다.
그래서 이 장과 다음 장은 앱 코드를 잠시 미뤄 둔다.
화면에 글자 한 줄을 찍는 프로그램에서 출발해 문법만 따로 익힌 뒤, {ch-go-sqlite}부터 작은 앱의 실제 코드로 들어가는 순서다.

이 장에서 다루는 것은 다섯 가지다.
첫 프로그램을 실행하는 방법, 변수와 기본 자료형, 상수, 함수와 다중 반환값, 그리고 조건문과 반복문이다.
마지막에는 이 다섯 가지를 모두 쓴 36줄짜리 프로그램을 하나 만들고, Go 컴파일러가 초보자의 실수를 어떻게 미리 잡아 주는지도 확인한다.
구조체와 목록처럼 데이터를 묶는 문법은 {ch-go-types}의 몫이다.

*이 장과 {ch-go-types}의 코드는 앱 코드가 아니라 연습용 예제다.*
책의 다른 장은 Flashcard의 실제 코드를 인용하지만, 여기서는 문법 하나에 예제 하나를 붙이는 편이 낫다고 판단했다.
완결된 프로그램은 저장소의 `language-basic/go/` 아래에 있고, 문법 하나를 보여 주는 짧은 조각은 원고에만 적었다.
전부 파일 하나로 도는 짧은 프로그램이니 직접 따라 실행해 보기를 권한다.
Go 컴파일러는 {ch-first-run}에서 설치해 앱을 띄울 때 이미 썼으므로, 준비물은 갖춰져 있다.

== 첫 프로그램: Hello, World

=== 파일 하나로 시작한다

빈 폴더를 하나 만들고 그 안에 `main.go`라는 이름으로 파일을 만든다.
내용은 빈 줄을 빼면 다섯 줄이 전부다.

[source,go]
----
include::../../language-basic/go/hello/main.go[]
----

첫 줄의 `package main`은 이 파일이 어느 꾸러미에 속하는지 밝히는 선언이다.
관련된 코드를 한데 모아 둔 이 묶음을 패키지(package)라고 부른다.
Go의 모든 소스 파일은 이 선언으로 시작하며, `main`이라는 이름은 특별하다.
"이 패키지는 라이브러리가 아니라 실행할 수 있는 프로그램"이라는 뜻이라, Go는 여기서 `main` 함수를 찾아 프로그램을 시작한다.
패키지를 어떻게 나누고 폴더를 어떻게 배치하는지는 {ch-code-map}에서 다루므로, 지금은 "첫 줄에 늘 오는 선언"으로 받아들이면 된다.

둘째 줄의 `import "fmt"`는 남이 만들어 둔 코드를 이 파일에서 쓰겠다는 선언이다.
`fmt`(format의 줄임말)는 화면에 글자를 찍고 값을 보기 좋게 다듬는 일을 맡은 패키지다.

.[용어 풀이] 임포트(import)
[NOTE]
====
다른 파일이나 남의 패키지에 있는 코드를 이 파일에서 쓰겠다고 맨 위에 밝히는 선언이고, 거기 적는 이름을 임포트 경로라고 한다.
요리를 시작하기 전에 냉장고에서 꺼내 올 재료부터 목록으로 적어 두는 것과 같다.
임포트하지 않은 패키지의 이름은 코드에서 쓸 수 없으므로, 파일을 열어 맨 위 목록만 봐도 그 파일이 무엇에 기대고 있는지 다 드러난다.
====

`fmt`를 어디서도 내려받지 않았는데 쓸 수 있는 이유는 이것이 Go를 설치할 때 함께 들어오는 표준 라이브러리이기 때문이다.

.[용어 풀이] 표준 라이브러리(Standard Library)
[NOTE]
====
언어를 설치하면 함께 따라오는 기본 부품 모음이다.
Go의 표준 라이브러리에는 글자 출력(`fmt`)뿐 아니라 HTTP 서버(`net/http`), JSON 변환(`encoding/json`), 시간 처리(`time`), 파일과 환경 변수 다루기(`os`)가 이미 들어 있어서, 남의 코드를 하나도 받아 오지 않고 웹 서버 한 대를 띄울 수 있다.
새로 이사한 집에 냉장고와 세탁기가 이미 붙어 있는 것과 같다.
바깥 라이브러리를 적게 쓸수록 버전 충돌이나 관리가 끊긴 코드에 발목 잡힐 일이 줄어들기 때문에, 이 두꺼움이 {ch-tech-choices}에서 Go를 고른 이유 중 하나였다.
====

나머지 세 줄이 `main` 함수다.
함수(function)는 명령 몇 개를 묶어 이름을 붙여 둔 것이고, 그 이름을 적어 안의 명령을 실행하는 것을 "부른다"고 한다.
직접 만드는 문법은 뒤의 함수 절에서 다루므로 지금은 이 두 낱말만 챙기면 된다.
`func`는 함수를 선언하는 키워드이고, 중괄호 `{`와 `}` 사이가 함수의 몸통이다.
`fmt.Println(...)`은 "`fmt` 패키지의 `Println` 함수를 부른다"고 읽는다.
점은 소속을 나타내고, `Println`은 print line, 즉 괄호 안의 값을 찍고 줄을 바꾸라는 뜻이다.

=== go run과 go build

Go는 컴파일 언어라, 사람이 쓴 소스 코드를 기계가 실행할 수 있는 형태로 한 번 번역한 뒤에 돌린다.
번역과 실행을 한 번에 하는 명령이 `go run`이다.
파일을 만든 폴더에서 아래 두 줄을 차례로 실행한다.

[source,shell]
----
go mod init example
go run .
----

첫 줄은 이 폴더가 Go 프로그램 하나임을 알리는 `go.mod` 파일을 만든다(이 파일의 정체는 {ch-code-map}에서 다룬다).
둘째 줄이 실행이고, 결과는 이렇다.

[source,text]
----
Hello, World!
----

`go run`은 번역 결과를 임시로 만들었다가 실행이 끝나면 버린다.
배포할 실행 파일을 남기려면 `go build`를 쓴다.

[source,shell]
----
go build -o hello .
./hello
----

이러면 `hello`라는 파일 하나가 생기고, 같은 운영체제와 CPU를 쓰는 컴퓨터라면 Go가 설치되어 있지 않아도 이 파일만으로 프로그램이 돈다.
다른 운영체제용 파일이 필요하면 빌드할 때 대상을 지정해 따로 만든다.
{ch-tech-choices}에서 Go의 장점으로 꼽은 "결과물이 파일 하나"라는 성질을 여기서 직접 확인할 수 있다.
{ch-vercel}에서 이 성질이 배포를 얼마나 간단하게 만드는지 다시 다룬다.

=== 문장의 끝은 줄바꿈이다

다섯 줄짜리 코드에서 미리 짚어 둘 표기 규칙이 있다.
C, 자바, C#은 문장 끝에 세미콜론(`;`)을 찍어 여기까지가 한 문장이라고 알린다.
Go는 줄바꿈이 그 일을 하므로 줄 끝에 아무 기호도 적지 않고, 한 줄이 곧 한 문장이다.
이 세 언어는 `if`의 조건을 괄호로 감싸지만, 조금 뒤에 볼 Go의 `if`는 조건에 괄호를 씌우지 않는다.

대신 형식에는 엄격하다.
여는 중괄호는 반드시 같은 줄 끝에 붙여야 하고, 들여쓰기는 공백이 아니라 탭이며, 이런 형식은 논쟁 대상이 아니다.
`gofmt`라는 도구가 코드를 정해진 모양으로 다시 써 주기 때문이다.
편집기의 Go 확장은 파일을 저장할 때 이 도구를 돌리고, 이 저장소에서는 에이전트가 Go 파일을 고칠 때마다 훅이 `gofmt -w`를 적용한다({ch-quality-gates}).
손으로 돌리려면 `gofmt -w 파일이름`이다.
"중괄호를 어디에 둘 것인가" 같은 취향 논쟁이 Go 프로젝트에 없는 것이 이 도구의 성과이고, 자세한 이야기는 {ch-unit-tests}에서 다룬다.

주석도 짚어 두자.
`//`로 시작하면 그 줄의 나머지는 사람이 읽는 설명이고 컴파일러는 무시한다.
여러 줄을 묶어 감싸려면 `/*`와 `*/` 사이에 넣는다.

[source,go]
----
// 카드를 몇 장 맞혔는지 센다.
correct := 5
----

== 변수와 기본 자료형

=== 변수를 만드는 두 가지 방법

변수는 값에 이름을 붙여 두는 상자다.
Go에서 변수를 만드는 방법은 두 가지다.

[source,go]
----
var deckName string = "토익 필수 단어"
cardCount := 8
----

첫 줄이 정식 선언으로, `var 이름 타입 = 값` 순서로 적는다.
둘째 줄이 단축 선언 `:=`이고, 타입을 적지 않았는데도 `cardCount`는 정수가 된다.
오른쪽 값이 정수이므로 컴파일러가 왼쪽의 타입을 알아서 정하기 때문이다.

.[용어 풀이] 타입 추론(Type Inference)
[NOTE]
====
변수의 타입을 사람이 적지 않아도 컴파일러가 대입하는 값을 보고 알아내는 기능이다.
`count := 8`이라고만 써도 `count`가 정수라는 사실이 확정되므로, 타입을 적는 수고는 덜면서 타입이 정해져 있는 이점은 그대로 누린다.
타입을 적지 않았다고 해서 아무 값이나 담을 수 있는 상자가 되는 것은 아니다.
`count`는 이 순간부터 끝까지 정수이고, 나중에 글자를 넣으려 하면 실행 전에 컴파일 에러가 난다.
====

두 형태의 중요한 차이는 쓸 수 있는 자리다.
`:=`는 함수 안에서만 쓸 수 있고, 함수 바깥에 두는 변수는 `var`로 선언해야 한다.
그래서 관례도 "함수 안에서는 짧은 `:=`, 함수 밖에서는 `var`"로 굳어져 있다.

=== 기본 자료형 네 가지

일상적으로 쓰는 타입은 네 가지면 시작할 수 있다.

[source,go]
----
var deckName string = "토익 필수 단어"
cardCount := 8
ease := 2.5
finished := false
----

|===
| 타입 | 담는 값 | 예

| `string` | 글자들의 나열 | `"토익 필수 단어"`, `"apple"`
| `int` | 정수 | `8`, `-3`, `0`
| `float64` | 소수점이 있는 숫자 | `2.5`, `0.32`
| `bool` | 참과 거짓 두 값 | `true`, `false`
|===

이 네 가지가 앞으로 읽을 코드의 대부분을 차지한다.
Flashcard에서 덱 이름과 카드 앞뒷면은 `string`, 카드 수와 연속 정답 횟수는 `int`, 복습 간격을 늘리는 배율은 `float64`, 정답 여부는 `bool`이다.
정수에는 크기를 지정하는 `int8`, `int64` 같은 변형도 있지만, 특별한 이유가 없으면 `int`를 쓴다.
`float32`가 아니라 `float64`가 기본인 것도 마찬가지다.

=== 값을 넣지 않으면 제로값에서 출발한다

선언만 하고 값을 주지 않으면 어떻게 될까.

[source,go]
----
var empty string
var zero int
var flag bool
fmt.Printf("[%s] [%d] [%t]\n", empty, zero, flag)
----

실행하면 이렇게 나온다.

[source,text]
----
[] [0] [false]
----

`fmt.Printf`는 `Println`과 달리 출력 모양을 직접 지정하는 함수다.
함수를 부를 때 괄호 안에 건네는 값을 인자(argument)라고 하는데, `Printf`의 첫 인자는 출력 모양을 적어 둔 문자열이고 그 뒤의 인자들이 그 모양에 차례로 끼워 넣을 값이다.
첫 인자의 `%s`, `%d`, `%t`는 "여기에 문자열을, 여기에 정수를, 여기에 참거짓을 끼워 넣으라"는 자리 표시이고, `\n`은 줄바꿈이다.
결과에서 보듯 세 변수에는 각각 빈 문자열, 0, `false`가 들어 있다.
이렇게 타입마다 정해진 기본값을 제로값이라고 한다.

.[용어 풀이] 제로값(Zero Value)
[NOTE]
====
변수를 선언만 하고 값을 넣지 않았을 때 타입마다 정해져 채워지는 기본값이다.
숫자는 `0`, 문자열은 빈 문자열 `""`, 불리언은 `false`이고, {ch-go-types}에서 볼 슬라이스와 포인터는 "없음"을 뜻하는 `nil`이다.
새 공책을 펼치면 언제나 백지가 나오는 것과 같아서, 초기화를 잊어도 변수는 늘 예측 가능한 상태에서 출발한다.
메모리에 남아 있던 쓰레기값을 실수로 읽는 사고가 아예 생기지 않는다.
====

별것 아닌 규칙처럼 보이지만, {ch-core-logic}에서 이 성질을 이용해 타입을 설계하는 방식을 보게 된다.
"아직 한 번도 복습하지 않은 카드"의 연속 정답 횟수와 복습 간격이 마침 0이어서, 아무 값도 채우지 않은 상태가 그대로 올바른 초기 상태가 되는 식이다.

=== 타입이 다르면 섞이지 않는다

Go는 타입이 다른 값을 소리 없이 섞어 주지 않는다.
정답 5개와 전체 7개로 정답률을 구한다고 해 보자.

[source,go]
----
correct := 5
total := 7.0
fmt.Println(correct / total)
----

이 코드는 실행되지 않는다.
컴파일러가 이렇게 거절한다.

[source,text]
----
./main.go:8:14: invalid operation: correct / total (mismatched types int and float64)
----

`correct`는 정수이고 `total`은 실수여서 나눌 수 없다는 뜻이다.
Go는 한쪽을 다른 쪽 타입으로 알아서 맞춰 주지 않고, 사람이 변환을 직접 적기를 요구한다.

[source,go]
----
total := 7
correct := 5
rate := float64(correct) / float64(total)
fmt.Printf("정답률 %.1f%%\n", rate*100)
----

`float64(correct)`가 변환이다.
타입 이름을 함수처럼 써서 값을 그 타입으로 바꾼다.

[source,text]
----
정답률 71.4%
----

`%.1f`는 소수점 아래 한 자리까지 찍으라는 지정이고, `%%`는 퍼센트 기호 자체를 찍는 표기다.
변환이 번거로워 보이지만, 이 번거로움이 막아 주는 사고가 있다.
변환하지 않고 둘 다 정수로 두면 어떻게 될까.

[source,go]
----
total := 7
rate := 5 / total
fmt.Println(rate)
----

[source,text]
----
0
----

정수끼리 나누면 소수점 아래가 잘려 나가 결과가 0이 된다.
에러도 경고도 없이 조용히 틀린 값이 나오는 이런 계산이 실무에서 흔한 버그이고, Go가 타입 변환을 명시하게 하는 이유가 여기 있다.
단위가 다른 숫자가 소리 없이 섞이는 일을 언어 차원에서 어렵게 만들어 둔 것이다.

=== 문자열 다루기

문자열은 큰따옴표로 감싸고, 더하기 기호로 잇는다.

[source,go]
----
fmt.Println("덱 이름은 " + deckName + "이다")
fmt.Println(len(deckName), len("card"))
----

[source,text]
----
덱 이름은 토익 필수 단어이다
20 4
----

`len`은 길이를 재는 내장 함수인데, 결과를 보면 이상하다.
`"card"`는 4가 맞지만 `"토익 필수 단어"`는 여덟 글자인데 20이 나왔다.
Go의 `len`이 글자 수가 아니라 바이트 수를 세기 때문이다.
한글은 한 글자에 3바이트를 쓰므로 여섯 글자에 공백 둘을 더해 20이 된다.

한글을 다루는 앱을 만들 때 한 번은 부딪히는 문제라 미리 적어 둔다.
글자 수를 세려면 `utf8.RuneCountInString`을 쓰거나, 문자열을 `[]rune`으로 바꿔 길이를 잰다.
다만 Flashcard가 문자열에 하는 일은 앞뒤 공백 걷어 내기(`strings.TrimSpace`, 테스트를 뺀 코드에서 29곳), 잇기(`strings.Join`, 8곳), 소문자로 바꾸기(`strings.ToLower`, 5곳), 자르기(`strings.Split`과 `strings.Cut`, 4곳)이고, 글자 수를 세는 곳은 한 군데도 없어서 이 구별이 필요한 자리가 없다.
그런 조작은 `strings` 패키지에 함수로 이미 준비되어 있다({ch-core-logic}에서 다시 다룬다).

=== 상수

한 번 정하면 프로그램이 도는 내내 바뀌지 않는 값은 `const`로 선언한다.

[source,go]
----
const initialEase = 2.5
const minEase = 1.3

const (
	statusNew    = "new"
	statusLearn  = "learning"
	statusReview = "review"
)
----

여러 개를 선언할 때는 위처럼 괄호로 묶을 수 있다.
`import`도 여러 줄일 때 같은 방식으로 묶는다.

상수를 쓰는 이유는 두 가지다.
첫째, 숫자 2.5나 문자열 `"learning"`을 코드 곳곳에 그대로 적어 두면 나중에 값을 바꿀 때 고칠 곳을 일일이 찾아다녀야 하고, 하나만 놓쳐도 버그가 된다.
둘째, 이름이 값의 의미를 설명한다.
`2.5`라고만 적힌 숫자는 무엇인지 알 수 없지만 `initialEase`는 "새 카드가 출발하는 용이도"라고 스스로 말한다.
{ch-core-logic}에서 읽을 간격 반복 알고리즘의 `srs.go`에는 같은 뜻의 상수가 `InitialEase`(2.5)와 `MinEase`(1.3)라는 이름으로 있다.

== 함수

=== 입력과 출력을 적는다

함수는 값을 받아 정해진 일을 하고 결과를 돌려주는 코드 묶음이다.
선언은 `func 이름(매개변수) 반환타입` 순서로 읽는다.

[source,go]
----
func nextInterval(days float64, ease float64) float64 {
	return days * ease
}
----

`nextInterval`은 지금 복습 간격과 배율을 받아 다음 간격을 돌려주는 함수다.
괄호 안의 `days float64`가 매개변수(건네받는 값)이고, 괄호 뒤의 `float64`가 돌려주는 값의 타입이다.
변수 선언과 마찬가지로 이름이 먼저 오고 타입이 뒤에 온다.
`return`이 결과를 돌려주며 함수를 끝낸다.

부를 때는 이렇게 쓴다.

[source,go]
----
fmt.Println(nextInterval(6, 2.5))
----

[source,text]
----
15
----

=== 값을 두 개 돌려준다

여기서부터가 Go의 특징이다.
Go 함수는 결과를 하나가 아니라 여러 개 돌려줄 수 있다.
정답률을 구하는 함수를 다시 만들어 보자.
카드를 한 장도 채점하지 않았다면 전체가 0이라 나눌 수 없으므로, 이 함수는 실패할 수 있다.

[source,go]
----
func accuracy(correct int, total int) (float64, error) {
	if total == 0 {
		return 0, errors.New("채점한 카드가 없다")
	}
	return float64(correct) / float64(total), nil
}
----

반환 타입이 `(float64, error)` 둘이다.
앞이 계산 결과이고 뒤가 "실패했는가"를 담는 값이다.
성공하면 결과와 함께 `nil`(에러 없음)을 돌려주고, 실패하면 의미 없는 값 0과 함께 에러를 돌려준다.
`errors.New`는 메시지를 담은 에러 값을 만드는 표준 라이브러리 함수다.

실패를 반환값으로 돌려주는 것은 프로그램이 오류를 다루는 두 가지 방식 중 하나다.
나머지 하나는 예외다.

.[용어 풀이] 예외(Exception)
[NOTE]
====
함수 안에서 문제가 생겼을 때, 그 자리에서 값을 돌려주는 대신 오류를 호출한 쪽으로 저절로 튀어 올려 보내는 장치다.
튀어 오르는 오류를 받아 내는 그물을 `try`/`catch`처럼 따로 쳐 두어야 하고, 아무도 받지 않으면 프로그램이 멈춘다.
성공하는 경로만 적으면 되니 코드가 짧아지지만, 함수의 선언만 봐서는 어떤 오류가 튀어 오를지 알기 어렵고 받아 내는 곳을 빠뜨려도 컴파일러가 알려 주지 않는다.
====

Go에는 오류를 튀어 올려 보내는 통로가 없고, 실패를 늘 반환값으로 손에 쥐여 준다.
부르는 쪽의 모양은 이렇다.

[source,go]
----
rate, err := accuracy(5, 7)
if err != nil {
	fmt.Println("계산 실패:", err)
	return
}
fmt.Printf("정답률 %.2f\n", rate)
----

반환값 두 개를 `rate, err :=`로 한 번에 받고, 바로 다음 줄에서 `err`가 `nil`인지 확인한다.

.[용어 풀이] 다중 반환값과 에러 처리
[NOTE]
====
Go 함수는 결과를 하나가 아니라 여러 개 한꺼번에 돌려줄 수 있다.
이 성질을 이용해, 실패할 수 있는 함수는 "결과"와 "실패했는지 여부(error)"를 나란히 반환하고, 호출한 쪽은 그 실패 값부터 곧바로 확인한다.
실패가 반환값으로 눈앞에 놓이므로 확인을 빠뜨리기 어렵다.
====

"함수를 부르고, 바로 다음 줄에서 에러부터 확인한다"는 이 두 줄 묶음이 Go 코드 어디에서나 반복되는 기본 리듬이다.
낯설더라도 눈에 익혀 두는 편이 좋다.
반대로 이 확인을 건너뛴 코드는 모양부터 어색해서 눈에 띈다.

돌려받은 값 중 쓰지 않을 것이 있으면 밑줄 `_`로 버린다.

[source,go]
----
if _, err := accuracy(0, 0); err != nil {
	fmt.Println("계산 실패:", err)
}
----

[source,text]
----
계산 실패: 채점한 카드가 없다
----

이 코드에는 `if`의 또 다른 형태도 들어 있다.
조건 앞에 세미콜론으로 구분해 짧은 준비 문장을 넣을 수 있어서, 함수 호출과 에러 검사를 한 줄에 담았다.
세미콜론 앞이 준비 작업이고 뒤가 조건이다.
여기서 선언한 `err`는 이 `if` 블록 안에서만 살아 있다가 사라지므로, 바깥에 이름이 남지 않는다.

=== 이름의 첫 글자가 공개 범위다

어떤 이름을 남이 갖다 써도 되는지, 아니면 이 패키지 안에서만 쓸 것인지를 Go는 따로 선언하지 않는다.
이름의 첫 글자가 그 일을 대신한다.
대문자로 시작하면 다른 패키지에서 갖다 쓸 수 있고, 소문자로 시작하면 그 패키지 안에서만 쓸 수 있다.

지금까지 쓴 `fmt.Println`과 `errors.New`가 대문자로 시작하는 것도 그래서다.
남이 쓰라고 공개한 이름이기 때문이다.
반대로 우리가 만든 `accuracy`와 `nextInterval`은 소문자여서 이 파일이 속한 패키지 밖으로는 나가지 않는다.

.[용어 풀이] 공개와 비공개(exported·unexported)
[NOTE]
====
식별자(함수, 타입, 필드, 상수의 이름)가 대문자로 시작하면 패키지 밖으로 공개되고(exported), 소문자로 시작하면 그 패키지 안에서만 쓸 수 있다(unexported).
가게가 진열대에 내놓은 물건과 창고에만 둔 물건을 구분해 두듯, '남들이 갖다 써도 되는 것'과 '내부 사정이라 감춰 둘 것'을 이름의 첫 글자로 나눈다.
공개한 이름은 다른 패키지가 의지하기 시작하므로 나중에 바꾸기 어렵고, 감춰 둔 이름은 언제든 고칠 수 있다.
그래서 밖에서 정말 써야 하는 것만 대문자로 시작하게 두는 것이 Go의 관례다.
====

공개 범위가 이름에 새겨져 있으므로, 코드를 읽는 것만으로 어디까지가 바깥에 약속한 것인지 드러난다.
{ch-code-map}에서 이 규칙이 폴더 구조와 함께 어떻게 쓰이는지 확인한다.

== 조건과 반복

=== if

조건에 따라 다른 일을 하려면 `if`를 쓴다.

[source,go]
----
score := 72
if score >= 90 {
	fmt.Println("아주 잘 외웠다")
} else if score >= 60 {
	fmt.Println("조금 더 보자")
} else {
	fmt.Println("처음부터 다시")
}
----

[source,text]
----
조금 더 보자
----

조건은 괄호로 감싸지 않고, 본문의 중괄호는 생략할 수 없다.
실행할 문장이 한 줄이어도 중괄호를 써야 한다.
번거로워 보이지만, 나중에 줄을 하나 더 넣었는데 그 줄이 조건 밖에 놓여 버리는 부류의 실수를 막는다.
비교에 쓰는 기호는 `==`(같다), `!=`(다르다), `<`, `>`, `<=`, `>=`이고, 조건을 잇는 기호는 `&&`(그리고), `||`(또는), `!`(부정)다.

=== for

같은 일을 여러 번 되풀이하려면 반복문 `for`를 쓴다.
`for`는 적는 형태에 따라 횟수를 세는 반복도 되고, 조건이 참인 동안 도는 반복도 되고, 목록을 처음부터 끝까지 차례로 읽는 반복도 된다.

가장 기본이 되는 형태는 횟수를 세는 것이다.

[source,go]
----
for i := 1; i <= 3; i++ {
	fmt.Println(i, "번째 카드")
}
----

세미콜론으로 구분한 세 부분은 차례로 시작값, 계속할 조건, 매 회차 끝에 할 일이다.
`i++`는 `i`를 1 늘리라는 뜻이다.

[source,text]
----
1 번째 카드
2 번째 카드
3 번째 카드
----

세 부분 중 조건만 남기면 그 조건이 참인 동안 계속 도는 반복이 된다.

[source,go]
----
remaining := 3
for remaining > 0 {
	remaining--
}
----

세 부분을 모두 지우면 끝나지 않는 반복이 되고, 안에서 `break`로 빠져나온다.
이번 회차만 건너뛰고 다음으로 넘어가려면 `continue`를 쓴다.

실제 코드에서 가장 자주 보게 될 형태는 목록을 처음부터 끝까지 차례로 읽는 `range`다.

[source,go]
----
for _, correct := range []bool{true, false, true} {
	fmt.Println(correct)
}
----

`[]bool{true, false, true}`는 참거짓 세 개를 담은 목록이다.
이런 목록을 슬라이스라고 부르는데, 자세한 것은 {ch-go-types}에서 다루므로 지금은 "값을 여러 개 담아 둔 것" 정도로 보면 된다.
`range`는 매 회차에 순번과 값을 함께 준다.
여기서는 순번이 필요 없어 밑줄 `_`로 버리고 값만 `correct`로 받았다.
Go는 선언해 놓고 쓰지 않는 변수를 컴파일 에러로 처리하기 때문에, 안 쓸 자리는 이렇게 버리는 것이 관례다.

=== switch

값 하나를 여러 경우로 나눠 처리할 때는 `switch`가 `if`를 여러 번 잇는 것보다 읽기 좋다.

[source,go]
----
mode := "due"
switch mode {
case "deck":
	fmt.Println("덱 전체를 학습한다")
case "due":
	fmt.Println("복습할 카드만 학습한다")
default:
	fmt.Println("알 수 없는 모드")
}
----

[source,text]
----
복습할 카드만 학습한다
----

각 `case`는 실행을 마치면 자동으로 `switch`를 벗어난다.
해당하는 `case` 하나만 실행되고 그 아래 `case`로 흘러내리지 않으므로, 빠져나오라는 표시를 따로 적을 필요가 없다.
어느 경우에도 해당하지 않으면 `default`로 간다.

`switch` 뒤의 값을 비우고 각 `case`에 조건을 적는 형태도 있다.
이러면 조건이 여러 개인 `if`를 계단처럼 잇는 대신 평평하게 늘어놓을 수 있다.

[source,go]
----
switch {
case rate >= 0.8:
	return "잘함"
case rate >= 0.5:
	return "보통"
default:
	return "다시"
}
----

== 종합: 채점 결과를 요약하는 프로그램

지금까지 배운 것을 한 프로그램에 모아 보자.
카드 여러 장의 채점 결과를 받아 정답률을 계산하고 등급을 붙이는, 36줄짜리 프로그램이다.
저장소의 `language-basic/go/grade/main.go`에 있으니 그 폴더에서 `go run .`으로 직접 돌려 볼 수도 있다.

[source,go]
----
include::../../language-basic/go/grade/main.go[]
----

[source,text]
----
7장 중 5장 정답, 정답률 71%
평가: 보통
----

이 안에 이 장의 문법이 모두 들어 있다.
패키지 선언과 임포트, 상수(`passMark`), 함수와 다중 반환값(`accuracy`), 반복문과 조건문(`for`와 `if`), 조건형 `switch`(`grade`), 타입 변환(`float64(...)`), 그리고 `fmt.Printf`의 자리 표시다.
`accuracy`가 정답률과 정답 수 두 개를 돌려주는 것도 눈여겨보자.
에러가 아니어도 서로 붙어 다니는 결과 두 개를 함께 돌려주는 데 다중 반환을 쓸 수 있다.
이름은 같지만 앞의 함수 절에서 만든 `accuracy`와는 받는 값도 돌려주는 값도 다르다.
앞에서는 정답 수와 전체 수를 받아 정답률과 에러를 돌려줬고, 여기서는 채점 결과 목록 하나를 받아 정답률과 정답 수를 돌려준다.
같은 이름의 함수라도 무엇을 받아 무엇을 돌려주는지는 선언 한 줄에서 확인하면 된다.

{ch-core-logic}에서 읽을 Flashcard의 간격 반복 알고리즘도 이 프로그램과 같은 재료로 짜여 있다.
카드의 상태와 정답 여부, 지금 시각을 받아 다음 복습 상태와 복습 예정 시각 두 개를 돌려주는 함수 `srs.Grade(s State, correct bool, now time.Time) (State, time.Time)` 하나가 그 알고리즘의 본체다.

== 컴파일러가 먼저 읽는다

Go를 처음 쓸 때 자주 만나는 벽이 하나 있다.
쓰지 않는 변수와 임포트를 컴파일 에러로 처리한다는 규칙이다.

[source,go]
----
package main

import (
	"fmt"
	"os"
)

func main() {
	count := 8
	fmt.Println("카드를 세어 보자")
}
----

`os`를 임포트해 놓고 쓰지 않았고, `count`를 선언해 놓고 쓰지 않았다.
쓰지 않을 것을 남겨 두었을 뿐이니 프로그램의 동작에는 아무 문제가 없는데도, 이 코드는 아예 실행되지 않는다.

[source,text]
----
./main.go:5:2: "os" imported and not used
./main.go:9:2: declared and not used: count
----

처음에는 성가시지만 이 엄격함에는 값이 있다.
쓰지 않는 임포트가 쌓이면 그 파일이 무엇에 기대고 있는지 알 수 없게 되고, 쓰지 않는 변수는 대개 "여기서 값을 쓰려다 말았다"는 흔적, 즉 미완성 코드의 신호다.
앞서 본 타입 불일치도 마찬가지다.
Go는 프로그램을 실행하기 전에 이런 문제를 모두 잡아낸다.

이 성질은 AI 에이전트와 일할 때 특히 값지다.
에이전트가 그럴듯하게 쓴 코드에 이름 오타나 타입 불일치가 섞여 있어도, 실행하기 전에 컴파일러가 파일과 줄 번호를 짚어 준다.
{ch-claude-code}에서 다룬 "에이전트의 결과를 무엇으로 검증할 것인가"라는 질문에 언어가 내놓는 첫 번째 답이 컴파일러다.
{ch-unit-tests}에서 여기에 테스트와 정적 분석을 더하고, {ch-quality-gates}에서 그 검사들을 자동으로 도는 품질 게이트로 묶는다.

== 직접 해 보기

`language-basic/go/grade/main.go`를 고쳐 가며 확인해 보자.
그 폴더에서 `go run .`을 실행하면 결과가 바로 나오므로, 한 줄 고치고 한 번 돌리는 리듬으로 하면 된다.

. 출력에 틀린 개수를 한 줄 더한다. `accuracy`가 돌려주는 값과 `len(results)`만 있으면 새 반복문 없이 계산할 수 있다.
. `passMark` 상수를 0.9로 바꾸고 다시 실행해 평가가 어떻게 달라지는지 본다. 상수 하나가 판정 기준을 쥐고 있다는 것이 값에 이름을 붙이는 이유다.
. `main` 함수 안에 쓰지 않을 변수를 하나 선언하고 실행해 본다. 프로그램이 아예 컴파일되지 않고 `declared and not used`라는 오류가 나올 것이다. 어느 줄인지까지 알려 주는 이 잔소리가 Go가 실수를 미리 잡아 주는 방식이다.
. `results`를 빈 목록(`[]bool{}`)으로 바꿔 실행한다. 0으로 나누는 사고가 나지 않는 이유를 `accuracy` 안에서 찾아본다.

== 에이전트 활용 아이디어

문법을 익히는 단계에서 에이전트를 쓰는 요령이다.

문법 질문은 답을 받는 데서 끝내지 말고 실행해 보게 한다.
"Go에서 `:=`와 `var`의 차이를 설명해 달라"보다 "차이가 드러나는 20줄 이하 프로그램을 만들고 `go run`으로 실행한 결과까지 보여 달라"가 낫다.
설명은 그럴듯하게 틀릴 수 있지만 실행 결과는 그렇지 않고, 이 장의 예제들이 모두 그렇듯 Go는 파일 하나로 실험할 수 있어 확인 비용이 적다.

컴파일 에러 메시지는 그대로 붙여 넣는 것이 가장 빠르다.
Go의 에러 메시지는 파일, 줄 번호, 원인이 한 줄에 들어 있어 에이전트가 곧바로 원인을 짚는다.
"에러가 났다"고만 말하고 코드를 다시 설명하는 것보다 짧게 끝난다.

에러 처리 관례는 지시문에 못 박아 두자.
"돌려받은 에러를 `_`로 버리지 말고 반드시 검사하라"고 적어 두면, 에러 검사를 건너뛴 코드가 리뷰까지 흘러오지 않는다.
갓 배운 사람에게 `if err != nil`이 반복되는 코드는 지저분해 보이지만, 이 반복이 Go 코드의 정상적인 모습이다.

== 정리

첫째, Go 프로그램은 `package` 선언, `import`, 함수로 이뤄지고 `main` 함수에서 시작한다.
`go run .`으로 곧바로 실행하고, `go build`로 Go 없이도 도는 실행 파일 하나를 만든다.

둘째, 변수는 함수 안에서 `:=`로 만들고 타입은 컴파일러가 추론한다.
기본 자료형은 `string`, `int`, `float64`, `bool` 네 가지로 시작하면 되고, 값을 넣지 않은 변수는 타입별 제로값(`""`, `0`, `false`)에서 출발한다.
타입이 다른 값은 `float64(x)`처럼 명시적으로 변환해야 섞인다.

셋째, 함수는 값을 여러 개 돌려줄 수 있고, 실패할 수 있는 함수는 마지막 반환값으로 `error`를 돌려준다.
"함수를 부르고, 바로 다음 줄에서 에러부터 확인한다"(`if err != nil`)가 Go 코드의 기본 리듬이다.
이름이 대문자로 시작하면 패키지 밖으로 공개된다.

넷째, 제어문은 단출하다.
`if`는 조건에 괄호를 쓰지 않고 중괄호를 생략할 수 없으며, 반복은 `for`로 하고 목록은 `range`로 하나씩 읽는다.
`switch`는 `case`마다 자동으로 끝나고, 조건을 나열하는 형태로도 쓴다.

다섯째, 되풀이해 쓰는 고정값은 `const`로 이름 붙여 한곳에 모은다.
그리고 쓰지 않는 변수와 임포트, 타입 불일치는 실행 전에 컴파일러가 잡는다.

다음 장에서는 값 하나가 아니라 값의 묶음을 다룬다.
카드 한 장을 표현하는 구조체, 카드 여러 장을 담는 슬라이스와 맵, 그리고 타입이 다른 데이터를 같은 코드로 다루는 인터페이스를 같은 방식으로 작은 예제부터 익혀 보자.
