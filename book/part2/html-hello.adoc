= HTML 첫걸음: 파일 하나로 만드는 웹 문서

{ch-first-run}에서 우리는 완성된 앱을 내 컴퓨터에 띄우고 브라우저로 이리저리 눌러 봤다.
그때 브라우저에 뜬 화면 하나하나가 전부 HTML(HyperText Markup Language) 문서다.
서버가 뒤에서 무슨 일을 하든 사용자 눈앞에 도착하는 것은 결국 이 문서이므로, 세 언어의 첫걸음도 화면의 언어에서 시작한다.

이 장에서 화면의 구조를 맡는 HTML을, {ch-css-hello}에서 겉모습을 입히는 CSS(Cascading Style Sheets)를 가장 단순한 예제로 익힌다.
앱의 실제 화면 파일은 아직 열지 않는다.
여기서 익힌 문법은 {ch-gin-hello·template-hello}에서 최소 앱의 화면을 만들며 곧바로 쓴다.
완성본 쪽은 {ch-html-css}에서 이 눈으로 실제 화면 파일을 읽고, {ch-html-template}에서 Go 서버가 그 파일에 데이터를 채워 넣는 방법을, {ch-htmx}에서 화면 일부만 갈아 끼우는 실전 패턴을 다룬다.

이 장에는 반가운 소식이 하나 있다.
HTML은 컴파일러도 서버도 필요 없이, 브라우저만 있으면 된다.
텍스트 파일 하나를 만들어 브라우저로 열면 그것이 곧 웹 페이지다.
이 장의 예제도 모두 그렇게 확인할 수 있는 연습용 코드다.
다만 폼 절의 카드 추가 폼만은 2부에서 만들 최소 앱에 그대로 얹을 것이라, 입력 칸 이름과 보낼 주소를 그 앱에 맞춰 두었다.

== 첫 문서: 파일 하나를 브라우저로 연다

빈 폴더에 `index.html`이라는 파일을 만들고 아래 내용을 적는다.

[source,html]
----
include::../../language-basic/html/first.html[]
----

이 파일을 브라우저로 열면(더블클릭하거나 브라우저 창에 끌어다 놓으면) 큰 제목 "내 단어장"과 그 아래 한 문단이 보인다.
탭에는 "내 단어장"이라고 뜬다.
파일을 고치고 저장한 뒤 브라우저에서 새로고침하면 결과가 곧바로 바뀌는데, 이 짧은 왕복이 화면 작업의 기본 리듬이다.

++++
<div class="fc-shots">

![첫 HTML 문서를 브라우저로 연 화면](/screenshots/html-first.png)

</div>

<p class="fc-caption">그림 5 첫 문서를 브라우저로 연 화면. CSS는 한 줄도 쓰지 않았지만 브라우저가 제목은 크고 굵게, 문단은 그보다 작게 그린다.</p>
++++

문서의 기본 구조는 정해져 있다.
맨 위의 `<!doctype html>`은 "이것은 HTML 문서다"라는 선언이고, 그 아래 `<html>`이 문서 전체를 감싼다.
`<html>` 안은 둘로 나뉜다.
`<head>`에는 화면에 직접 보이지 않는 문서 정보가, `<body>`에는 화면에 보이는 내용이 들어간다.

`<head>` 안의 두 줄도 짚어 두자.
`<meta charset="utf-8">`은 글자를 어떤 방식으로 저장했는지 알려 주는 선언인데, 이 줄이 없으면 브라우저에 따라 한글이 깨져 보인다.
`<title>`은 브라우저 탭에 뜨는 제목이고, 검색 결과와 즐겨찾기에도 이 문장이 쓰인다.
`<html lang="ko">`의 `lang`은 이 문서가 한국어라고 밝혀서 자동 번역과 화면 낭독기가 참고하게 한다.
화면 낭독기(screen reader)는 화면의 내용을 소리로 읽어 주는 프로그램인데, 뒤의 시맨틱 마크업 절에서 자세히 다룬다.

== 태그와 요소

HTML은 프로그래밍 언어가 아니라 마크업 언어다.
계산하거나 판단하지 않고, 글에 "여기까지는 제목", "이것은 문단"이라고 표시만 한다.
그 표시가 꺾쇠로 감싼 태그다.

[source,html]
----
<p>오늘 외울 카드가 3장 있다.</p>
----

`<p>`가 여는 태그, `</p>`가 닫는 태그이고, 둘 사이에 낀 것이 그 태그가 표시하는 내용이다.
여는 태그부터 닫는 태그까지 한 덩어리를 요소라고 부른다.

.[용어 풀이] HTML 태그와 요소(tag, element)
[NOTE]
====
태그는 `<p>`처럼 꺾쇠로 감싼 표식이고, 요소는 여는 태그부터 닫는 태그까지의 한 덩어리(`<p>안녕</p>`)다.
문서에 "여기까지는 문단", "이것은 버튼"이라고 이름표를 붙이는 문법이며, `charset="utf-8"`처럼 태그 안에 붙는 추가 정보는 속성(attribute)이라고 부른다.
====

태그 안에는 속성을 적을 수 있다.
`<a href="/decks">덱 목록</a>`에서 `href`가 속성 이름이고 `"/decks"`가 그 값이다.
속성은 그 요소에 주는 추가 지시라고 보면 된다.
링크에는 갈 주소를, 이미지에는 파일 위치를, 입력 칸에는 이름을 속성으로 준다.

닫는 태그가 없는 태그도 있다.
`<meta>`, `<img>`, `<input>`, `<br>`처럼 안에 담을 내용이 없는 것들이라 여는 태그 하나로 끝난다.

주석은 `<!--`와 `-->` 사이에 쓴다.
화면에는 보이지 않지만 문서에는 남아 있으므로, 비밀은 적지 않는 것이 좋다.

[source,html]
----
<!-- 여기부터 덱 목록 -->
----

.[용어 풀이] 주석(comment)
[NOTE]
====
코드나 문서에 사람이 읽으라고 적어 두는 메모다.
브라우저나 컴파일러 같은 기계는 이 부분을 건너뛰므로, 무엇을 적어도 동작은 달라지지 않는다.
표기는 언어마다 다르다.
HTML은 `<!--`와 `-->`로 감싸고, CSS는 `/*`와 `*/`({ch-css-hello}), Go는 줄 앞에 `//`({ch-go-hello})를 붙인다.
코드만 봐도 알 수 있는 "무엇을 하는가"보다, 코드에 드러나지 않는 "왜 이렇게 했는가"를 적어 두는 편이 쓸모 있다.
====

== 글의 구조를 잡는 태그

가장 많이 쓰는 태그는 열 개 남짓이다.
앞의 문서를 조금 늘려 보자.

[source,html]
----
<body>
  <h1>내 단어장</h1>

  <h2>토익 필수 단어</h2>
  <p>카드 3장</p>

  <ul>
    <li><strong>apple</strong> 사과</li>
    <li><strong>banana</strong> 바나나</li>
    <li><strong>cherry</strong> 체리</li>
  </ul>

  <a href="/decks/toeic">덱 자세히 보기</a>
</body>
----

`<h1>`부터 `<h6>`까지가 제목이고, 숫자가 작을수록 큰 제목이다.
이 숫자는 글자 크기가 아니라 문서의 계층을 뜻한다.
`<h1>`은 문서 전체의 제목으로 한 페이지에 하나만 두고, 그 아래 절의 제목이 `<h2>`, 그 아래가 `<h3>`이다.
글자 크기가 마음에 들지 않는다고 `<h3>`을 쓰는 것은 좋지 않다.
크기는 {ch-css-hello}에서 CSS로 정하면 되고, 태그는 구조를 위해 남겨 둔다.

`<p>`는 문단이다.
줄을 바꾸고 싶다고 `<br>`을 여러 개 넣는 대신, 문단마다 `<p>`로 감싸는 것이 바른 방법이다.

`<ul>`은 순서 없는 목록(unordered list)이고 그 안의 항목 하나가 `<li>`(list item)다.
순서가 의미를 지니면 `<ul>` 대신 `<ol>`(ordered list)을 쓰고, 그러면 번호가 자동으로 붙는다.
목록은 카드 목록, 덱 목록, 메뉴처럼 같은 모양이 반복되는 곳 어디에나 쓰인다.

`<strong>`은 중요한 부분, `<em>`은 강조할 부분을 표시한다.
겉으로는 굵은 글씨와 기울인 글씨로 보이지만, 이름이 `<b>`나 `<i>`가 아니라 `strong`과 `em`인 데는 이유가 있다.
"굵게 보여라"가 아니라 "중요하다"라고 적어 두면 화면 낭독기가 그 부분을 힘주어 읽을 수 있다.

`<a>`는 링크다.
`href` 속성의 주소로 사용자를 데려간다.
웹에서 화면과 화면을 잇는 가장 기본적인 방법이고, Flashcard에서도 화면 사이의 이동은 대부분 이 태그가 맡는다.
브라우저가 새 주소를 요청하면 서버가 새 문서를 보내 주는, 웹이 처음부터 쓰던 이동 방식이다.

그림을 넣을 때는 `<img>`를 쓴다.

[source,html]
----
<img src="/images/apple.png" alt="사과 사진">
----

`src`는 이미지 파일의 위치이고, `alt`는 이미지를 볼 수 없을 때 대신 읽을 설명이다.
`alt`는 선택이 아니라 필수에 가깝다.
이미지가 깨졌을 때, 통신이 느릴 때, 그리고 화면 낭독기를 쓰는 사용자에게 이 문장이 유일한 정보이기 때문이다.

== 의미를 담은 태그: 시맨틱 마크업

지금까지의 문서에는 상단 제목 부분과 본문의 경계가 없다.
경계를 만들려면 감싸는 태그가 필요한데, 여기에도 이름 있는 태그가 준비되어 있다.

[source,html]
----
<body>
  <header>
    <h1>내 단어장</h1>
  </header>

  <nav>
    <a href="/">홈</a>
    <a href="/decks">덱</a>
    <a href="/stats">통계</a>
  </nav>

  <main>
    <section>
      <h2>토익 필수 단어</h2>
      <p>카드 3장</p>
    </section>
  </main>

  <footer>
    <p>혼자 쓰는 암기 카드 앱</p>
  </footer>
</body>
----

`<header>`는 문서나 구획의 머리말, `<nav>`는 이동 메뉴, `<main>`은 이 페이지의 주된 내용, `<section>`은 관련 내용을 묶는 구획, `<footer>`는 꼬리말이다.
의미를 따지지 않고 그냥 상자만 필요할 때 쓰는 태그도 있다.
`<div>`는 덩어리를 감싸는 의미 없는 상자이고, `<span>`은 문장 속 일부를 감싸는 의미 없는 표시다.

이 다섯 개를 전부 `<div>`로 바꿔도 화면은 똑같이 나온다.
그런데도 이름 있는 태그를 쓰는 이유가 셋 있다.
화면 낭독기는 `<nav>`를 만나면 "여기는 이동 메뉴"라고 알려 줄 수 있고, 검색 엔진은 `<main>` 안의 내용을 그 페이지의 본문으로 대접하며, 사람에게도 코드가 목차처럼 읽힌다.
이렇게 태그로 구조의 의미까지 표현하는 것을 시맨틱 마크업이라고 부른다.

.[용어 풀이] 시맨틱 마크업(semantic markup)
[NOTE]
====
"이 부분은 제목, 여기는 메뉴, 여기가 본문"처럼 문서의 각 부분이 무엇인지를 그 의미에 맞는 태그로 표시하는 습관이다.
모든 것을 `<div>`로 만들어도 겉모습은 같지만, 같은 내용의 책이라도 목차와 장 제목이 있는 쪽이 읽기 쉬운 것과 같은 이치로 낭독기·검색 엔진·동료 개발자가 의미를 얻는다.
====

.[용어 풀이] 화면 낭독기(screen reader)
[NOTE]
====
화면에 있는 것을 소리로 읽어 주는 프로그램이다.
눈으로 화면을 보기 어려운 사용자가 웹을 쓰는 통로이며, 글자만 읽는 것이 아니라 "여기는 이동 메뉴", "버튼, 정답 보기"처럼 각 부분이 무엇인지도 함께 알려 준다.
그러려면 문서가 그 정보를 담고 있어야 하므로, `lang` 속성이나 시맨틱 태그처럼 겉모습에 드러나지 않는 표시가 낭독기에는 중요한 단서가 된다.
이런 사용자까지 화면을 쓸 수 있게 만드는 일을 접근성(accessibility)이라고 부른다.
====

== 이름표: class와 id

태그 이름만으로는 부족할 때가 있다.
문단이 스무 개인데 그중 안내 문구 세 개만 흐리게 만들고 싶다면, "이 부류"를 가리킬 이름이 필요하다.
그 이름표가 `class`다.

[source,html]
----
<ul class="list">
  <li class="item">apple 사과</li>
  <li class="item">banana 바나나</li>
</ul>
<p class="item-empty">아직 카드가 없다</p>
----

`class="item-empty"`는 화면에 아무 변화도 주지 않는다.
{ch-css-hello}에서 CSS가 이 이름을 찾아 "흐리게"라는 규칙을 붙일 때 비로소 뜻이 생긴다.
지금은 요소에 붙여 둔 이름표라고만 보면 된다.
이 이름들도 카드 추가 폼처럼 최소 앱과 맞춰 둔 것이라, {ch-css-hello}와 {ch-template-hello}에 같은 이름으로 다시 나온다.

하나뿐인 요소를 콕 집어야 할 때는 `id`를 쓴다.

[source,html]
----
<input id="text" name="text">
----

`id="text"`가 이 입력 칸을 문서에서 하나뿐인 이름으로 짚는 이름표다.
같이 붙은 `name`은 서버가 값을 찾을 때 쓰는 다른 이름표인데, 아래 폼 절에서 다시 설명한다.

.[용어 풀이] class와 id
[NOTE]
====
요소에 붙이는 두 가지 이름표다.
`class`는 같은 이름을 여러 요소에 붙일 수 있어 "이런 부류 전체"를 가리키고, `id`는 문서 안에서 하나뿐이어야 해서 "바로 그 요소 하나"를 가리킨다.
학교로 치면 class는 같은 반 학생이 모두 다는 반 이름표, id는 학생마다 다른 학번이다.
CSS는 이 이름표로 꾸밀 대상을 찾고, 요소끼리 연결할 때(`<label for="text">`)나 {ch-htmx}에서 화면의 어느 자리를 갈아 끼울지 정할 때도 id로 그 자리를 짚는다.
====

한 요소에 클래스를 여러 개 붙일 수도 있다.
`class="item wrong"`처럼 공백으로 나열하면 두 이름표를 함께 단 것이고, 공통 모양은 `item`이, 틀린 카드에만 붙는 표시는 `wrong`이 맡는 식으로 나눠 쓴다.

== 요소의 가족 관계

HTML은 태그가 태그를 품는 나무 모양의 구조다.
그래서 요소들이 놓인 자리를 가계도의 낱말로 부른다.

[source,html]
----
<ul class="list">
  <li class="item">apple 사과</li>
  <li class="item">banana 바나나</li>
</ul>
----

`<ul>`은 두 `<li>`의 부모이고, 두 `<li>`는 서로 형제다.
`<ul>`에서 보면 `<li>`가 자식이고, 두 단계 이상 안쪽에 있는 요소는 자손이다.

.[용어 풀이] 요소의 가족 관계(부모·자식·형제·조상·자손)
[NOTE]
====
HTML은 태그가 태그를 품는 나무 모양의 구조라({ch-htmx}에서 볼 DOM이 이 나무다), 요소들이 놓인 자리를 가계도의 낱말로 부른다.
감싼 쪽이 부모(parent), 그 안에 든 쪽이 자식(child)이고, 한 부모 아래 나란히 선 요소들은 서로 형제(sibling)다.
두 단계 이상 바깥으로 올라가면 조상(ancestor), 두 단계 이상 안으로 내려가면 자손(descendant)이다.
이 낱말들이 그대로 {ch-css-hello}에서 배울 CSS 선택자의 문법이 된다.
====

이 관계가 중요한 이유는 {ch-css-hello}에서 드러난다.
"목록 안의 항목"이나 "선택된 버튼 바로 다음 요소"처럼, 요소를 위치로 짚는 것이 CSS의 주요 수단이기 때문이다.
그래서 HTML을 짤 때 태그를 어떻게 중첩하는지가 나중에 스타일을 얼마나 편하게 쓸 수 있는지를 정한다.

== 폼: 값을 서버로 보낸다

지금까지는 서버가 브라우저로 보내는 방향이었다.
반대 방향, 즉 사용자가 입력한 것을 서버로 보내는 표준 도구가 폼이다.

.[용어 풀이] 폼(form)
[NOTE]
====
사용자가 채운 값을 모아 서버로 보내는 HTML의 표준 묶음이다.
`<form>`으로 감싸고 그 안에 입력 칸과 제출 버튼을 두면, 버튼을 누르는 순간 브라우저가 값을 모아 서버로 요청을 보낸다.
종이 신청서를 작성해 창구에 내는 일과 같아서, 어느 창구에 어떤 방식으로 낼지는 태그의 속성에 적어 둔다.
값을 모아 실어 보내는 일은 브라우저가 맡으므로 자바스크립트가 필요 없고, 로그인·검색·글쓰기까지 웹의 입력은 대부분 이 도구 위에 서 있다.
====

카드를 하나 추가하는 폼을 만들어 보자.
여기서 만드는 폼은 연습으로 끝나지 않는다.
{ch-template-hello}에서 최소 앱(`flashcard-basic/`)에 얹을 카드 추가 폼이 바로 이것이라, 입력 칸의 이름과 보낼 주소도 그 앱에 맞춰 둔다.

[source,html]
----
<form method="post" action="/decks/1/cards">
  <label for="text">앞면</label>
  <input id="text" name="text" placeholder="apple" required>

  <label for="meaning">뒷면</label>
  <input id="meaning" name="meaning" required>

  <button type="submit">카드 추가</button>
</form>
----

`<form>`의 두 속성이 핵심이다.
`action`은 어디로 보낼지(주소)이고, `method`는 어떻게 보낼지다.
여기서 "어떻게"란 서버에 무엇을 해 달라는 것인지 요청의 종류를 뜻하고, 이 종류를 부르는 이름이 HTTP 메서드(method)다.
주소의 `1`은 카드를 담을 덱의 번호인데, 지금은 손으로 적었지만 최소 앱에서는 서버가 보고 있는 덱의 번호로 채워 넣는다({ch-gin-hello}).
`method="post"`의 POST는 "새로 만들어 달라"는 요청이고, 이런 요청의 종류는 {ch-gin-hello}에서 처음 실제로 쓰고 {ch-gin}에서 자세히 다룬다.
"카드 추가" 버튼을 누르면 브라우저가 입력 값을 모아 `POST /decks/1/cards` 요청을 보내고, 서버가 카드를 만든 뒤 새 화면으로 안내한다.
`method="get"`이면 값이 주소 뒤에 붙어 전달되며, 검색처럼 결과를 다시 찾아갈 수 있어야 하는 경우에 쓴다.

`<input>`은 한 줄 입력 칸이다.
여기서 가장 중요한 속성은 `name`이다.
서버는 이 이름표로 값을 찾으므로, `name`이 없는 입력 칸의 값은 아예 전송되지 않는다.
`placeholder`는 비어 있을 때 흐리게 보이는 안내 문구이고, `required`는 비워 두면 제출을 막는 검사다.
검사를 브라우저가 대신해 주므로 자바스크립트를 쓰지 않고도 빈 값 제출을 막을 수 있다.

`<label>`은 입력 칸의 이름표다.
`for` 속성에 입력 칸의 `id`를 적어 둘을 연결하는데, 이러면 라벨을 눌러도 그 입력 칸이 선택된다.
좁은 화면에서 누를 수 있는 영역이 넓어지고, 화면 낭독기가 "앞면, 입력 칸"이라고 함께 읽어 준다.
`<label>`이 `<input>`을 감싸는 형태로 써도 자동으로 연결된다.

입력 칸의 종류는 `type` 속성이 정한다.

[source,html]
----
<input type="text" name="text">
<input type="number" name="count" min="1" max="100">
<input type="file" name="file" accept=".csv">
<input type="checkbox" name="shared" value="yes">
<input type="radio" name="card_type" value="word">
<input type="radio" name="card_type" value="sentence">
----

`type="number"`는 숫자만 받고 위아래 화살표를 붙이며, `type="file"`은 파일 선택 창을 띄운다.
`type="checkbox"`는 켜고 끄는 값이고, `type="radio"`는 `name`이 같은 것끼리 한 묶음이 되어 그중 하나만 선택된다(옛날 라디오의 채널 버튼에서 온 이름이다).
`value`는 그 칸이 선택됐을 때 서버로 갈 값이다.
`name`이 서버가 값을 찾는 이름표라면, `value`는 그 이름표에 담겨 갈 내용이다.
라디오 두 줄의 `name`이 `card_type`으로 같은 것도 그래서다.
어느 쪽을 고르든 서버는 `card_type`이라는 이름으로 값을 받고, 고른 쪽의 `value`(`word` 또는 `sentence`)가 그 내용이 된다.
여러 줄을 받으려면 `<textarea>`, 목록에서 하나를 고르게 하려면 `<select>`와 `<option>`을 쓴다.

[source,html]
----
<textarea name="example" rows="3"></textarea>

<select name="direction">
  <option value="front-back">앞면 보고 뒷면 맞히기</option>
  <option value="back-front">뒷면 보고 앞면 맞히기</option>
</select>
----

여기서 눈여겨볼 것은 이 모든 동작에 자바스크립트가 한 줄도 없다는 사실이다.
값 모으기, 필수 검사, 파일 선택 창, 라디오 버튼 묶음이 전부 브라우저에 내장되어 있다.
Flashcard가 화면 대부분을 폼으로 처리하는 이유가 여기 있다.
최소 앱에서 폼으로 서버에 값을 보내는 것은 {ch-gin-hello}에서 덱 만들기로 처음 해 보고, 방금 만든 카드 추가 폼이 실제로 카드를 저장하는 것은 {ch-template-hello}에서 확인한다.
완성본 앱의 폼은 {ch-html-css}에서 읽는다.

== 문서에 꼭 넣어야 할 것들

마지막으로 처음 문서를 만들 때 넣어 두면 좋은 것을 모아 둔다.

[source,html]
----
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>내 단어장</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <!-- ... -->
</body>
</html>
----

`<meta name="viewport" ...>`는 모바일 브라우저에 "화면 폭에 맞춰 그리고 임의로 축소하지 말라"고 알린다.
이 한 줄이 없으면 스마트폰에서 페이지가 데스크톱 크기로 그려진 뒤 축소되어 글자가 깨알만 해진다.
휴대폰으로 쓸 화면이라면 빠뜨리면 안 되는 줄이다.

`<link rel="stylesheet" href="style.css">`는 CSS 파일을 불러오는 선언으로, 다음 장의 출발점이다.
`<link>`와 `<script>`처럼 바깥 파일을 불러오는 태그는 `<head>` 안에 둔다.

정리하면 새 문서를 시작할 때의 최소 준비물은 다섯 가지다.
doctype 선언, `lang` 속성, `charset`, `viewport`, 그리고 `<title>`이다.

== 직접 해 보기

읽기만 해서는 손에 붙지 않는다.
`language-basic/html/`의 파일을 고치고 브라우저에서 새로고침해 결과를 확인해 보자.
정답을 따로 싣지 않은 것은 화면이 곧 채점표이기 때문이다.

. `page.html`에 좋아하는 것을 소개하는 절을 하나 더 붙인다. `section`과 `h2`, 목록 태그를 쓰고, 그 절이 왜 `div`가 아니라 `section`인지 한 문장으로 설명할 수 있으면 된다.
. `form.html`에 "난이도"를 고르는 `select` 칸을 더한다. `label`의 `for`와 입력 칸의 `id`를 맞춰 두고, 글자를 눌렀을 때 칸으로 초점이 옮겨 가는지 확인한다.
. `first.html`에서 닫는 태그 하나를 일부러 지우고 브라우저로 연다. 오류 창이 뜨지 않고 화면이 어그러진 채 그려질 것이다. HTML은 잘못 적어도 알려 주지 않는다는 사실을 눈으로 확인해 두면, {ch-go-hello}에서 만날 컴파일러의 잔소리가 왜 고마운 것인지 알게 된다.

== 에이전트 활용 아이디어

HTML은 에이전트가 특히 빠르게 만들어 내는 영역이지만, 그만큼 습관적으로 잘못 쓰기도 쉽다.

지시문에 시맨틱 규칙을 못 박아 두면 결과가 달라진다.
"모든 것을 `<div>`로 만들지 말고 `header`, `nav`, `main`, `section`, `footer`를 쓰라", "이미지에는 반드시 `alt`를, 입력 칸에는 반드시 `<label>`을 붙이라"가 그 후보다.
그냥 두면 에이전트는 `<div>`와 `<span>`만으로 화면을 짜는 쪽으로 기운다.

접근성 점검은 에이전트가 잘하는 반복 작업이다.
"이 폴더의 HTML 전체에서 `alt`가 빠진 이미지, 라벨이 없는 입력 칸, `<h1>`이 없거나 둘 이상인 문서를 찾아 표로 보고해 달라"처럼 일괄 점검을 맡기면 사람이 놓치는 구석을 값싸게 확인할 수 있다.

화면 작업에는 컴파일러 같은 자동 검증이 없다는 점도 기억해 두자.
태그를 잘못 닫아도 브라우저는 어떻게든 그려 내므로 에러가 나지 않는다.
그래서 "바꾼 뒤 어느 화면의 무엇을 확인해야 하는지"를 에이전트가 목록으로 보고하게 하고, 사람이 브라우저로 그 목록을 눌러 보는 흐름이 현실적이다.

== 정리

첫째, HTML 문서는 doctype 선언, `<html>`, 그리고 `<head>`와 `<body>` 두 부분으로 이뤄진다.
텍스트 파일 하나를 브라우저로 열면 그것이 곧 웹 페이지이므로, 고치고 새로고침하는 짧은 왕복으로 실험할 수 있다.

둘째, 태그는 글에 이름표를 붙이는 표시이고 속성은 그 태그에 주는 추가 지시다.
제목은 `<h1>`부터 `<h6>`, 문단은 `<p>`, 목록은 `<ul>`과 `<li>`, 링크는 `<a>`, 이미지는 `<img>`가 맡는다.

셋째, 겉모습이 같더라도 의미에 맞는 태그를 쓴다.
`<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`는 화면 낭독기와 검색 엔진에 구조를 알려 주고, 의미가 필요 없을 때만 `<div>`와 `<span>`을 쓴다.

넷째, `class`는 부류를 가리키는 이름표이고 `id`는 하나뿐인 요소를 가리키는 이름표다.
요소들은 부모·자식·형제 관계로 놓이며, 이 관계가 다음 장의 CSS 선택자 문법이 된다.

다섯째, 사용자 입력은 폼이 맡는다.
`<form>`의 `action`과 `method`가 어디로 어떻게 보낼지를 정하고, `<input>`의 `name`이 서버가 값을 찾는 이름표가 된다.
필수 검사와 파일 선택, 라디오 버튼 묶음까지 브라우저가 내장 기능으로 처리한다.

다음 장에서는 이 문서에 겉모습을 입힌다.
색과 여백, 글자 크기, 상자를 늘어놓는 배치, 그리고 화면 크기와 테마에 따라 달라지는 규칙까지 CSS 하나로 정하는 방법을 살펴보자.
