= CSS 첫걸음: 색과 배치를 입히는 규칙

{ch-html-hello}에서 만든 문서를 브라우저로 열어 보면 글자만 검게 늘어서 있다.
제목은 크고 굵게, 문단은 그보다 작게 나오지만 그것이 전부다.
색도 여백도 배치도 없다.
브라우저가 태그마다 정해 둔 최소한의 모양만 적용하기 때문이다.

이 장의 주제인 CSS가 그 겉모습을 정한다.
색, 글자 크기, 여백, 테두리, 상자를 늘어놓는 배치, 화면 크기와 테마에 따라 달라지는 규칙이 모두 CSS 담당이다.
HTML이 "무엇인가"를 적는다면 CSS는 "어떻게 보일 것인가"를 적는다.

이번 장에서는 CSS를 문서에 붙이는 방법과 규칙 하나의 생김새에서 출발해 선택자, 색과 단위, 변수, 박스 모델, 플렉스박스와 그리드, 미디어 쿼리를 차례로 익힌다.
마지막에는 {ch-html-hello}의 문서에 입힐 스타일시트 하나를 완성한다.

이 장의 예제도 {ch-html-hello}처럼 최소 앱과 이름을 맞춰 둔다.
변수 이름과 클래스 이름이 {ch-gin-hello·template-hello}에서 읽을 `flashcard-basic/static/style.css`의 것이고, 마지막에 완성하는 스타일시트가 그 파일의 축소판이다.
{ch-html-css}에서 읽을 완성본의 스타일시트도 규모만 다를 뿐 이 문법의 조합이므로, 여기까지 익히면 그 파일을 처음부터 끝까지 따라갈 수 있다.

== CSS를 문서에 붙이는 세 가지 방법

CSS를 HTML에 연결하는 방법은 세 가지다.

첫째는 별도 파일로 두고 불러오는 것이다.
{ch-html-hello}의 문서와 같은 폴더에 `style.css`를 만들고, `<head>` 안에 한 줄을 넣는다.

[source,html]
----
<link rel="stylesheet" href="style.css">
----

둘째는 문서 안에 `<style>` 태그로 직접 적는 것이고, 셋째는 요소마다 `style` 속성으로 적는 것이다.

[source,html]
----
<p style="color: red">이 방법은 권하지 않는다</p>
----

셋 중 첫째를 쓴다.
스타일이 한곳에 모여 있어야 같은 규칙을 여러 화면이 나눠 쓸 수 있고, 색을 하나 바꿀 때 고칠 곳도 하나이기 때문이다.
셋째 방법은 요소마다 규칙이 흩어져 같은 값을 수십 번 반복하게 되므로, Flashcard의 프로젝트 지침({ch-claude-code}에서 본 `CLAUDE.md`)에도 "템플릿에 인라인 `style` 속성을 두지 않는다"고 못 박혀 있다.
그 지침이 허용하는 예외는 하나, 진행률 막대처럼 서버가 계산한 값을 넣어야 하는 `style="width:{{.ProgressPct}}%"` 같은 자리뿐이다.
여기서 템플릿은 서버가 데이터를 채워 넣어 화면을 만들어 내는 HTML 원본 파일이다.
그 문법은 {ch-template-hello}에서 익히므로, 지금은 "HTML 파일에도 같은 규칙이 적용된다" 정도로 읽으면 된다.

== 규칙 하나의 생김새

CSS 파일에 첫 규칙을 적어 보자.

[source,css]
----
p {
  color: #666677;
}
----

읽는 법은 "누구에게, 무엇을"이다.
중괄호 앞의 `p`가 꾸밀 대상을 고르는 선택자이고, 중괄호 안이 적용할 내용이다.
`color`가 속성 이름, `#666677`이 값이며, 선언 하나가 끝날 때마다 세미콜론을 찍는다.
위 규칙은 "모든 문단의 글자색을 회색으로"라고 읽는다.

한 규칙에 선언을 여러 개 넣을 수 있고, 여러 선택자를 쉼표로 이어 같은 규칙을 나눠 쓸 수도 있다.

[source,css]
----
h1, h2 {
  color: #1f2430;
  margin-bottom: 0.5rem;
}
----

CSS에도 주석이 있다.
`/*`와 `*/` 사이가 주석이며, HTML의 `<!-- -->`와는 표기가 다르다.

== 선택자: 누구를 고를 것인가

CSS 작업의 절반은 "이 규칙을 어느 요소에 적용할 것인가"를 정하는 일이다.

.[용어 풀이] CSS 선택자(selector)
[NOTE]
====
CSS 규칙을 문서의 어느 요소에 적용할지 고르는 문법이다.
태그 이름(`input`), 클래스(`.button`), 상태(`:checked`), 관계(자손·형제)를 조합해 "선택된 라디오 버튼 바로 뒤의 알약"처럼 요소 하나를 짚을 수 있다.
완성본 `app.css`의 `.pill-radio:checked + .pill-label`이 바로 그 선택자다.
문서 전체에서 조건에 맞는 요소를 찾아 주는 검색어인 셈이다.
====

=== 태그, 클래스, id

가장 기본은 태그 이름을 그대로 적는 것이다.
`p`는 모든 문단, `a`는 모든 링크를 고른다.
글꼴이나 입력 칸 모양처럼 문서 전체에 통일할 것을 정할 때 알맞다.

두 번째는 클래스 선택자로, {ch-html-hello}에서 붙여 둔 이름표 앞에 점을 찍는다.

[source,css]
----
.item-empty {
  color: #666677;
}
----

`class="item-empty"`가 붙은 요소만 고른다.
최소 앱에서 "아직 덱이 없다" 같은 안내 문구에 붙일 이름표다.
태그 선택자가 "모든 문단" 같은 넓은 그물이라면 클래스는 원하는 요소에만 붙이는 이름표다.
완성본 `app.css`의 규칙 194개 가운데 클래스로 고르는 규칙이 160개이고, 태그로 고르는 규칙은 26개, id로 고르는 규칙은 2개다.

세 번째는 id 선택자로 우물 정 기호를 앞에 붙인다(`#text`).
문서에 하나뿐인 요소를 고를 때 쓰지만, CSS에서는 아껴 쓰는 편이 낫다.
뒤에서 볼 우선순위가 지나치게 높아 나중에 예외를 주기 어려워지기 때문이다.

=== 관계로 고르기

{ch-html-hello}에서 본 가족 관계가 여기서 문법이 된다.

[source,css]
----
.list .item {
  border: 1px solid #d8dce4;
}
----

선택자 두 개를 공백으로 이으면 자손 선택자다.
"`list` 클래스가 붙은 요소 안에 들어 있는 `item` 요소"를 고른다.
공백 대신 `>`를 쓰면 바로 아래 자식만, `+`를 쓰면 바로 다음 형제, `~`를 쓰면 뒤에 오는 형제들을 고른다.

여기서 트레이드오프를 하나 짚어 두자면, 태그 구조에 기대는 대신 요소마다 이름표를 달아 `.item`처럼 평평하게 고르는 편이 안전하다.
`.list li`처럼 태그에 기대어 고르면 편하지만, 나중에 템플릿에서 그 `<li>`를 다른 태그로 바꾸거나 감싸는 태그를 하나 더 두는 순간 스타일이 조용히 풀린다.
컴파일 오류도 테스트 실패도 나지 않고 화면만 어긋나므로 알아채기 어렵다.
그래서 {ch-claude-code}에서 본 Flashcard의 프로젝트 지침도 이 방식을 원칙으로 삼는다.
이름을 하나 더 짓는 비용을 치르고, 태그를 바꿔도 스타일이 따라오는 안정성을 얻는 선택이다.

=== 상태로 고르기

콜론으로 시작하는 선택자는 요소의 지금 상태를 짚는다.

[source,css]
----
.navlink:hover {
  text-decoration: underline;
}

.field:focus {
  outline: 2px solid #2456c8;
}
----

`:hover`는 마우스를 올린 동안, `:focus`는 커서가 그 입력 칸에 들어와 있는 동안이다.
최소 앱의 입력 칸에 붙은 이름표가 `field`라, 두 번째 규칙은 그 앱에 그대로 들어 있다.
`:checked`는 체크박스나 라디오 버튼이 선택된 상태를 고르는데, 이것이 자바스크립트 없이 화면을 바꾸는 열쇠가 된다.
사용자가 무언가를 선택했다는 사실을 HTML 요소가 들고 있고 CSS가 그것을 읽어 겉모습만 바꾸는 방식이라, {ch-html-css}에서 볼 카드 뒤집기가 정확히 이 원리로 동작한다.

대괄호로 속성을 짚는 선택자도 있다.
`.study[open]`은 "`study` 클래스가 붙었고 `open` 속성이 켜진 요소"를 고른다.
{ch-template-hello}에서 읽을 학습 화면은 이 한 줄로 "펼쳐진 뒤에는 안내 문구를 지운다"를 해결한다.
여기서 `open`은 사람이 적어 두는 이름표가 아니다.
접었다 펼치는 `<details>`라는 요소가 있는데, 사용자가 그것을 펼치는 순간 브라우저가 `open` 속성을 붙이고 접으면 도로 뗀다.
그래서 이 선택자는 "사용자가 펼친 뒤"라는 상태를 자바스크립트 없이 읽어 낸다.

== 여러 규칙이 겹칠 때

같은 요소에 여러 규칙이 해당하면 무엇이 이길까.

[source,css]
----
.item {
  background: #ffffff;
}

.item.wrong {
  background: #fde8e8;
}
----

CSS라는 이름의 첫 단어 캐스케이드(cascade)는 "폭포처럼 흘러내린다"는 뜻이고, 여기에 우선순위 규칙이 있다.
더 구체적인 선택자가 이기고, 구체성이 같으면 나중에 적힌 규칙이 이긴다.
클래스 두 개를 요구하는 `.item.wrong`이 `.item` 하나보다 구체적이므로, 두 이름표를 모두 단 요소는 붉은 배경이 된다.

구체성 계산을 전부 외울 필요는 없다.
"넓은 규칙을 앞에, 좁은 예외를 뒤에"라는 순서 감각과, "id 선택자와 `!important`는 우선순위를 지나치게 올리므로 아껴 쓴다"는 원칙이면 대부분 충분하다.

== 색과 길이

=== 색

색은 세 가지 표기를 주로 쓴다.
`red`, `white` 같은 이름, `#2456c8` 같은 16진수, `rgb(36, 86, 200)` 같은 숫자 표기다.
16진수 표기는 빨강·초록·파랑을 두 자리씩 적은 것으로, `#000000`이 검정이고 `#ffffff`가 흰색이다.
`#f7f8fa`처럼 세 값이 비슷하면 회색 계열이고, 값이 클수록 밝다.

색을 고르는 일 자체는 이 책의 주제가 아니지만, 실용적인 기준이 하나 있다.
웹 접근성 지침(WCAG)은 본문 글자색과 배경색의 명도 대비를 4.5:1 이상으로 요구한다footnote:[W3C, Web Content Accessibility Guidelines 2.1의 성공 기준 1.4.3 https://www.w3.org/TR/WCAG21/#contrast-minimum[Contrast (Minimum)]].
이 장 끝의 스타일시트에서 흐린 글자색 `--muted`(`#666677`)를 바탕색 `--paper`(`#f7f8fa`)에 올리면 대비가 5.3:1이고, 어두운 테마의 `#9aa0b0`를 `#14161b`에 올리면 6.9:1이라 두 테마 모두 이 기준을 넘긴다.
옅은 회색 글자를 옅은 배경에 올리면 이 값이 4.5 밑으로 떨어진다.

=== 길이 단위

길이 단위는 여러 가지가 있지만 두 개로 시작하면 된다.
`px`는 화면의 점 하나를 세는 절대 단위이고, `rem`은 브라우저의 기본 글자 크기를 1로 삼는 상대 단위다.

.[용어 풀이] rem(root em)
[NOTE]
====
브라우저의 기본 글자 크기를 1로 삼는 CSS 길이 단위다.
브라우저의 기본값은 16픽셀이라 `1rem`은 16픽셀, `0.75rem`은 12픽셀이 된다.
이 값이 달라지는 것은 사용자가 브라우저 설정에서 기본 글자 크기를 바꿨을 때뿐이다.
픽셀(`px`)이 자로 잰 절대 길이라면 `rem`은 글자 크기에 비례하는 상대 길이여서, 그 설정으로 글자를 키우면 여백과 둥근 모서리도 같은 비율로 함께 커진다.
글자만 커지고 상자는 그대로여서 화면이 어그러지는 사고를 막는 것이 이 단위를 쓰는 이유다.
====

글자 크기와 여백에는 `rem`을, 테두리 두께처럼 굵기가 변하면 곤란한 값에는 `px`를 쓰는 것이 무난한 기준이다.
너비에는 `%`도 자주 쓰는데, 부모 요소를 기준으로 한 비율이다.

== CSS 변수: 값에 이름을 붙인다

앱 전체에서 같은 파란색을 열 곳에서 쓴다고 하자.
`#2456c8`을 열 번 적어 두면 색을 바꿀 때 열 곳을 모두 고쳐야 하고, 하나만 놓쳐도 화면 어딘가에 옛 색이 남는다.
CSS에는 값에 이름을 붙여 두는 문법이 있다.

[source,css]
----
:root {
  --paper: #f7f8fa;
  --surface: #ffffff;
  --ink: #1f2430;
  --muted: #666677;
  --line: #d8dce4;
  --accent: #2456c8;
  --radius: 0.5rem;
}
----

`:root`는 문서의 뿌리, 즉 `<html>` 요소를 가리키는 선택자이고, 붙임표 두 개로 시작하는 이름이 CSS 변수다.
여기서 선언한 변수는 아래 어디서든 `var(--accent)`로 꺼내 쓴다.

[source,css]
----
.navlink {
  color: var(--accent);
}
----

이름을 무엇으로 지을지도 결정이다.
`--blue`처럼 색 자체를 이름으로 삼으면 나중에 파랑을 초록으로 바꿀 때 이름이 거짓말을 하게 되므로, `--accent`(강조색)나 `--paper`(바탕)처럼 쓰임새로 짓는다.

.[용어 풀이] CSS 변수(커스텀 프로퍼티, custom property)
[NOTE]
====
`--accent: #2456c8`처럼 값에 이름을 붙여 두고 `var(--accent)`로 꺼내 쓰는 CSS 기능이다.
공식 명칭은 커스텀 프로퍼티이지만 흔히 CSS 변수라고 부른다.
"우리 브랜드 파랑"을 물감 통 하나에 담아 두고 여기저기서 찍어 쓰는 것과 같아서, 색을 바꿀 때 물감 통 하나만 갈면 된다.
====

이렇게 이름 붙여 둔 색과 치수를 디자인 토큰(design token)이라고 부른다.
파일 맨 위에 토큰을 모아 두는 습관은 색을 바꾸기 쉽게 하는 데서 끝나지 않는다.
이 장 끝에서 볼 다크 모드가 변수 여섯 개의 값을 바꾸는 것만으로 따라온다.

== 박스 모델: 모든 것은 네모난 상자다

브라우저가 보기에 모든 요소는 네모난 상자다.
글자가 들어가는 내용이 있고, 그 둘레를 안쪽 여백(padding), 테두리(border), 바깥 여백(margin)이 겹겹이 둘러싼다.

[source,css]
----
.item {
  padding: 0.6rem 0.8rem;
  border: 1px solid var(--line);
  border-radius: var(--radius);
  margin-bottom: 0.5rem;
  background: var(--surface);
}
----

`padding: 0.6rem 0.8rem`처럼 값을 두 개 적으면 위아래가 첫 값, 좌우가 둘째 값이다.
값 하나면 네 방향 모두, 네 개면 위·오른쪽·아래·왼쪽 순서다.
`border: 1px solid var(--line)`은 두께·모양·색을 한 줄에 적는 축약 표기이고, `border-radius`는 모서리를 둥글게 깎는다.

.[용어 풀이] 박스 모델(box model)
[NOTE]
====
모든 HTML 요소를 내용, 안쪽 여백(padding), 테두리(border), 바깥 여백(margin)의 네 겹 상자로 보는 CSS의 기본 모형이다.
택배 상자에 비유하면 물건(내용), 완충재(패딩), 상자 벽(테두리), 상자 사이 간격(마진)이고, 요소의 크기와 간격은 대부분 이 네 겹 중 어디를 조절할지로 정해진다.
====

여기에 거의 관습이 된 규칙이 하나 있다.

[source,css]
----
* {
  box-sizing: border-box;
}
----

`*`는 모든 요소를 고르는 선택자다.
`box-sizing: border-box`는 "너비를 잴 때 테두리와 안쪽 여백까지 포함하라"는 뜻이다.
기본값대로 두면 `width: 100%`에 패딩을 준 요소가 딱 그 패딩만큼 부모 밖으로 삐져나오는데, 이 한 줄이 그 계산을 직관에 맞게 바꾼다.
새 스타일시트를 시작할 때 맨 앞에 적어 두면 좋은 규칙이다.

== 배치: 플렉스박스와 그리드

상자들을 어떻게 늘어놓을지가 배치다.
현대 CSS의 배치 도구는 크게 둘, 플렉스박스와 그리드다.

플렉스박스는 한 방향으로 줄 세우는 데 쓴다.

[source,css]
----
.item {
  display: flex;
  align-items: center;
  gap: 0.75rem;
}

.decklink {
  flex: 1;
}
----

`display: flex`를 준 요소의 자식들이 가로로 나란히 선다.
`align-items: center`가 세로 가운데를 맞추고, `gap`이 자식 사이의 최소 간격을 준다.
자식 요소에 준 `flex: 1`은 "남는 공간을 네가 다 가져라"라는 뜻이라, 덱 이름이 넓게 퍼지고 지우기 버튼은 오른쪽 끝으로 밀린다.
자식들을 양 끝으로 밀어 사이를 벌리는 `justify-content: space-between`으로도 같은 모양을 만들 수 있다.
세로로 쌓고 싶으면 `flex-direction: column`을 더한다.

좁은 화면을 위한 두 줄도 알아 두면 좋다.
`flex-wrap: wrap`은 한 줄에 다 들어가지 않으면 다음 줄로 넘기라는 뜻이고, 자식 요소에 주는 `min-width: 0`은 "내용보다 작게 줄어들어도 된다"는 허가다.
입력 칸은 `size` 속성의 기본값인 스무 글자 너비 밑으로 줄어들지 않으려 하기 때문에footnote:[MDN의 input 요소 문서에서 size 속성 항목 https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input[The HTML input element]], 이 허가가 없으면 좁은 화면에서 입력 칸이 버티고 옆의 버튼만 찌그러진다.
카드 추가 폼이 휴대폰에서도 멀쩡한 것은 이 두 줄 덕분이다.
이 장 끝의 완성한 스타일시트에서 폼을 감싸는 `.row`에 `flex-wrap: wrap`이, 그 안의 입력 칸 `.field`에 `min-width: 0`이 붙어 있는 것을 확인할 수 있다.
자식이 몇 개든 규칙을 고치지 않아도 알아서 다시 배분되는 이 유연함(flexible)이 이름의 유래다.

그리드는 행과 열이 있는 격자에 쓴다.

[source,css]
----
.stats {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 0.75rem;
}
----

`grid-template-columns: repeat(3, 1fr)`은 "같은 폭의 열 세 개"라는 선언이다.
`fr`은 남은 공간을 나눠 갖는 비율 단위라, `1fr 2fr`이면 두 열의 폭이 1대 2가 된다.
통계 숫자 세 칸이나 버튼 두 개를 반반으로 놓는 자리처럼, 칸이 격자로 놓이는 배치에 알맞다.
최소 앱의 화면은 한 줄짜리 목록뿐이라 그리드가 쓰이지 않지만, 완성본의 통계 화면과 채점 버튼은 이 문법으로 놓인다({ch-html-css}).

.[용어 풀이] 플렉스박스와 그리드(Flexbox, Grid)
[NOTE]
====
CSS의 두 가지 현대적 배치 도구다.
플렉스박스는 상자들을 한 방향으로 줄 세우고 간격과 정렬을 조절하는 데(예: 아이콘과 글자를 나란히), 그리드는 행과 열이 있는 격자에 상자들을 앉히는 데(예: 통계 3칸) 알맞다.
이 둘이 나오기 전에는 표 태그나 float 같은 우회 기법으로 배치를 흉내 냈다.
====

둘 중 무엇을 쓸지는 간단히 정할 수 있다.
한 줄로 흘러가는 배치에는 플렉스박스, 행과 열 양쪽으로 칸이 생기는 표 모양 배치에는 그리드다.

화면 전체의 폭과 위치를 잡을 때 자주 쓰는 조합도 알아 두면 좋다.

[source,css]
----
body {
  max-width: 40rem;
  margin: 0 auto;
}
----

`max-width`가 폭의 상한을 정하고, `margin: 0 auto`가 남는 좌우 공간을 균등하게 나눠 가운데로 보낸다.
휴대폰에서는 화면을 가득 채우고 큰 모니터에서는 가운데 좁은 기둥으로 서게 하는, 한 칼럼 화면의 기본 틀이다.

== 미디어 쿼리와 다크 모드

같은 문서가 휴대폰과 데스크톱에서 다르게 보여야 할 때가 있다.
조건을 걸고 그 조건이 참일 때만 규칙을 적용하는 문법이 미디어 쿼리다.

[source,css]
----
@media (min-width: 48rem) {
  .stats {
    grid-template-columns: repeat(6, 1fr);
  }
}
----

`@media (...)`는 "괄호 안 조건이 참일 때만 이 안의 규칙을 적용하라"는 뜻이다.
위 규칙은 화면 폭이 48rem 이상일 때만 통계를 여섯 칸으로 편다.
작은 화면을 기본으로 두고 큰 화면을 예외로 다루는 이 접근을 모바일 우선(mobile first)이라고 부른다.

.[용어 풀이] 미디어 쿼리(media query)
[NOTE]
====
"화면 폭이 이만큼 이상이면", "사용자가 어두운 테마를 켰으면"처럼 보는 환경에 조건을 걸고, 참일 때만 안쪽 CSS 규칙을 적용하는 문법이다.
같은 문서가 스마트폰, 태블릿, 어두운 방의 모니터에서 각각 알맞게 보이도록 하는 스위치다.
====

미디어 쿼리로 읽을 수 있는 것은 화면 크기만이 아니다.
사용자가 운영체제에서 고른 테마도 조건이 된다.

[source,css]
----
@media (prefers-color-scheme: dark) {
  :root {
    --paper: #14161b;
    --surface: #1f2430;
    --ink: #e8eaf0;
    --muted: #9aa0b0;
    --line: #333a49;
    --accent: #6f9bff;
  }
}
----

여기서 앞서 변수를 모아 둔 보상이 돌아온다.
바뀌는 것은 변수 값 여섯 개뿐이고, `background: var(--paper)`라고 적어 둔 나머지 규칙은 한 줄도 손대지 않았는데 화면 전체가 어두운 테마로 뒤집힌다.
변수 없이 다크 모드를 만들려면 색을 쓰는 규칙마다 어두운 버전을 한 벌씩 더 써야 하고, 색 하나를 빠뜨리면 어두운 배경에 검은 글자 같은 사고가 난다.

== 완성한 스타일시트

지금까지의 규칙을 모으면 {ch-html-hello}에서 만든 카드 목록과 카드 추가 폼에 입힐 스타일시트가 된다.
이 스타일시트가 꾸미는 문서는 `language-basic/html/page.html`이다.
{ch-html-hello}의 코드 조각에는 없던 이름표도 그 파일에는 미리 붙어 있다.
제목에 `title`, 이동 메뉴에 `nav`와 `navlink`, 카드 앞뒷면에 `card-front`와 `card-back`, 폼과 입력 칸과 버튼에 `row`·`field`·`button`이다.
아래 규칙의 이름이 낯설면 그 파일에서 같은 이름을 먼저 찾아보면 된다.

[source,css]
----
:root {
  --paper: #f7f8fa;
  --surface: #ffffff;
  --ink: #1f2430;
  --muted: #666677;
  --line: #d8dce4;
  --accent: #2456c8;
  --radius: 0.5rem;
}

* {
  box-sizing: border-box;
}

body {
  margin: 0 auto;
  max-width: 40rem;
  padding: 1.5rem 1rem;
  font-family: system-ui, sans-serif;
  line-height: 1.6;
  color: var(--ink);
  background: var(--paper);
}

.title {
  font-size: 1.4rem;
}

.nav {
  display: flex;
  gap: 1rem;
}

.navlink {
  color: var(--accent);
}

.list {
  margin: 1rem 0;
  padding: 0;
  list-style: none;
}

.item {
  display: flex;
  align-items: center;
  gap: 0.75rem;
  padding: 0.6rem 0.8rem;
  margin-bottom: 0.5rem;
  background: var(--surface);
  border: 1px solid var(--line);
  border-radius: var(--radius);
}

.item-empty {
  padding: 0.6rem 0.2rem;
  color: var(--muted);
}

.card-front {
  font-weight: 600;
}

.card-back {
  flex: 1;
  color: var(--muted);
}

.row {
  display: flex;
  flex-wrap: wrap;
  gap: 0.5rem;
}

.field {
  flex: 1 1 8rem;
  min-width: 0;
  padding: 0.5rem 0.7rem;
  border: 1px solid var(--line);
  border-radius: var(--radius);
  font: inherit;
  color: var(--ink);
  background: var(--surface);
}

.button {
  padding: 0.5rem 1rem;
  border: none;
  border-radius: var(--radius);
  background: var(--accent);
  color: #fff;
  font: inherit;
  white-space: nowrap;
  cursor: pointer;
}

@media (prefers-color-scheme: dark) {
  :root {
    --paper: #14161b;
    --surface: #1f2430;
    --ink: #e8eaf0;
    --muted: #9aa0b0;
    --line: #333a49;
    --accent: #6f9bff;
  }
}
----

`font-family: system-ui, sans-serif`는 운영체제의 기본 글꼴을 쓰라는 지정이다.
쉼표로 여러 개를 적으면 앞에서부터 쓸 수 있는 것을 고르므로, 마지막에 안전한 값을 두는 것이 관례다.
`line-height: 1.6`은 줄 간격을 글자 크기의 1.6배로 벌려 읽기 편하게 만든다.
`.list`의 `list-style: none`은 목록 앞의 점을 지우는데, 목록 태그를 쓰되 점은 보이지 않게 하고 싶을 때 쓰는 흔한 규칙이다.
입력 칸과 버튼에 붙인 `font: inherit`도 눈여겨보자.
브라우저는 `<input>`과 `<button>`에만 다른 글꼴과 크기를 기본으로 주기 때문에, 이 한 줄이 없으면 폼 안의 글자만 혼자 작아진다.
`.navlink`는 앞에서 본 링크 색 규칙이다.
브라우저가 링크에 기본으로 주는 짙은 파랑을 그대로 두면 어두운 배경에서 읽기 어려워지므로, 링크 색도 변수로 정해 둔다.

{ch-html-hello}에서 만든 문서에 이 파일을 `<link>`로 붙이면 화면이 이렇게 바뀐다.

![스타일 없는 화면, 스타일을 붙인 화면, 어두운 테마 화면을 나란히 놓은 비교](/screenshots/css-before-after.png)

</div>

<p class="fc-caption">그림 11 같은 문서를 스타일 없이 열었을 때(왼쪽), 이 스타일시트를 붙였을 때(가운데), 운영체제가 어두운 테마일 때(오른쪽). 오른쪽 화면에서 바뀐 것은 변수 여섯 개의 값뿐이다.</p>

이 스타일시트는 106줄이고, {ch-gin-hello·template-hello}에서 읽을 최소 앱의 `static/style.css`는 172줄이다.
여기 있는 규칙 열다섯 개가 그 파일에 그대로 들어 있고, 그 파일에는 규칙 열 개와 변수 하나(`--danger`)가 더 있다.
덱 목록의 `.decklink`와 지우기 버튼 `.delete`, 입력 칸의 `.field:focus`, 그리고 학습 화면(`details`)에 붙는 `.study`로 시작하는 규칙 일곱 개다.
그래서 2부를 마칠 때쯤이면 이 장에서 손으로 적어 본 규칙들이 실제로 도는 앱의 스타일이 되어 있다.

같은 구조가 {ch-html-css}에서 읽을 완성본의 스타일시트로도 이어진다.
그 파일은 1,250줄 남짓으로 더 길지만, 구조는 똑같다.
맨 위에 변수, 그 아래 `box-sizing`, 이어서 태그와 클래스 규칙, 그리고 다크 모드 미디어 쿼리다.

여기서 도구 선택의 트레이드오프를 하나 짚고 가자.
CSS를 맨손으로 쓰는 대신 변수와 중첩 문법을 보태 주는 전처리기 Sass, 미리 만든 유틸리티 클래스를 조립하는 Tailwind CSS, 완성된 부품을 주는 Bootstrap 같은 도구를 얹는 선택지도 있다.
팀이 크고 화면이 수백 개면 이런 도구가 일관성을 지키는 데 낫다.
하지만 이들을 쓰려면 빌드 도구와 의존성 관리가 따라온다.
게다가 전처리기가 내세우던 변수(방금 봤다)는 2017년부터, 규칙 안에 규칙을 적는 중첩은 2023년 말부터 주요 브라우저가 모두 지원해 전처리기를 쓸 이유가 예전만큼 크지 않다footnote:[브라우저별 지원 버전은 Can I use의 https://caniuse.com/css-variables[CSS Variables (Custom Properties)]와 https://caniuse.com/css-nesting[CSS Nesting] 항목에 있다. 변수는 Edge 16(2017년 10월)이, 중첩은 Chrome 120과 Safari 17.2(2023년 12월)가 마지막으로 합류했다.].
화면 템플릿이 13장인 1인 프로젝트라면 빌드 없이 파일 하나로 끝나는 순수 CSS가 알맞고, 이 선택의 전체 그림은 {ch-tech-choices}에서 정리했다.

== 직접 해 보기

`language-basic/html/style.css`와 `page.html`을 고쳐 가며 확인해 보자.
저장소의 `page.html`에는 스타일시트를 부르는 줄이 아직 없다.
스타일이 붙기 전과 붙은 뒤를 직접 견주어 볼 수 있도록 비워 둔 것이라, 그 한 줄을 넣는 일이 첫 과제다.
브라우저의 개발자 도구를 열어 두면 어느 규칙이 적용됐는지 그 자리에서 볼 수 있다.

브라우저에 내장된 점검 창이다.
지금 열려 있는 페이지의 HTML과 CSS, 오간 네트워크 요청, 브라우저에 저장된 캐시까지 들여다보고 그 자리에서 바꿔 볼 수도 있다.
Chrome에서는 F12를 누르거나(macOS는 ⌥⌘I), 화면에서 오른쪽 클릭 후 "검사"를 고르면 열린다.
화면에 나온 결과만으로는 원인을 알 수 없을 때 자동차의 보닛을 열어 엔진을 확인하는 일에 해당한다.
이 장에서는 요소 하나를 골라 그것이 어떤 HTML이고 어떤 CSS 규칙을 적용받는지 보는 데까지만 쓰고, 네트워크와 캐시를 살피는 탭은 {ch-htmx}과 {ch-caching}에서 쓴다.
====

. `page.html`의 `<head>` 안에 `style.css`를 부르는 줄을 하나 넣고 브라우저로 연다. 무엇을 적을지는 이 장 첫 절 "CSS를 문서에 붙이는 세 가지 방법"에 있다. 넣기 전에는 글자만 검게 늘어서 있고, 넣은 뒤에는 카드마다 흰 상자와 여백이 생긴다.
. 스타일시트 맨 위의 CSS 변수 가운데 색 하나를 바꾸고 새로고침한다. 한 줄을 고쳤는데 화면의 여러 곳이 함께 바뀐다면 변수를 제대로 쓴 것이다. 이어서 파일 끝의 다크 모드 블록에서 같은 변수를 손보고, 운영체제의 화면 모드를 바꾸거나 개발자 도구에서 어두운 모드를 흉내 내어 두 테마가 모두 읽히는지 확인한다.
. 카드 목록의 배치를 그리드로 바꿔 두 칸으로 늘어놓는다. 이어서 미디어 쿼리를 하나 더해 화면이 좁아지면 다시 한 칸이 되게 한다.
. 요소 하나에 `padding`과 `margin`을 크게 준 뒤 개발자 도구에서 그 요소를 골라 본다. 안쪽 여백과 바깥쪽 여백이 그림으로 구분돼 보이는 것이 이 장에서 본 박스 모델이다.

== 에이전트 활용 아이디어

CSS는 에이전트가 만들어 낸 결과를 사람이 눈으로 확인해야 하는 영역이라, 확인 비용을 줄이는 쪽으로 지시하는 것이 요령이다.

지시문에 스타일 규약을 적어 두지 않으면 에이전트는 인라인 스타일이나 유틸리티 클래스 흉내로 지름길을 내므로, 규약을 먼저 적어 둔다.
"CSS는 파일 하나만 쓰고 프레임워크와 전처리기를 쓰지 않는다", "색과 간격은 파일 상단의 변수로만 추가한다", "다크 모드가 있으므로 새 색은 두 팔레트에 모두 정의한다", "인라인 `style` 속성을 쓰지 않는다"가 그 후보다.

선택자 방침도 적어 둘 만하다.
"자손 선택자 대신 요소마다 클래스를 달아 평평하게 고른다"는 규칙은 코드만 봐서는 알 수 없는 판단이라, 적어 두지 않으면 매번 다른 방식으로 짜인다.

바꾼 뒤 확인할 목록을 요구하자.
"이 변경으로 겉모습이 달라지는 화면과 요소를 목록으로 알려 달라"고 덧붙이면, 사람이 브라우저에서 무엇을 눌러 봐야 하는지가 분명해진다.
{ch-claude-code}의 검토 기준으로 보면 화면 스타일은 오류를 발견하기 쉬운 영역이라, 빠르게 읽고 눈으로 확인하는 쪽에 힘을 싣는 것이 합리적이다.

== 정리

첫째, CSS는 별도 파일로 두고 `<link>`로 불러온다.
규칙 하나는 "선택자 { 속성: 값; }" 꼴이고, 선택자가 대상을 고른다.

둘째, 선택자는 태그 이름, 클래스(`.item`), id(`#text`), 관계(자손·자식·형제), 상태(`:hover`, `:focus`, `:checked`)를 조합한다.
태그 구조에 기대는 자손 선택자보다 요소마다 클래스를 달아 평평하게 고르는 편이 나중에 태그를 바꿔도 안전하다.
규칙이 겹치면 더 구체적인 것이, 구체성이 같으면 나중에 적힌 것이 이긴다.

셋째, 색은 16진수 표기를, 길이는 글자 크기에 비례하는 `rem`을 기본으로 쓴다.
되풀이되는 색과 치수는 `:root`에 CSS 변수로 모아 디자인 토큰을 만든다.

넷째, 모든 요소는 내용·패딩·테두리·마진의 네 겹 상자다.
`box-sizing: border-box`를 맨 앞에 한 번 선언해 크기 계산을 직관에 맞춘다.

다섯째, 배치는 한 방향 줄 세우기에 플렉스박스를, 격자에 그리드를 쓴다.
화면 크기나 테마 같은 조건은 미디어 쿼리로 걸고, 다크 모드는 변수 값만 갈아 끼우는 것으로 끝낸다.

여기까지가 화면을 만드는 두 재료다.
이 눈으로 Flashcard의 실제 화면 파일을 읽는 일은 {ch-html-css}의 몫이다.
1,250줄 남짓한 스타일시트가 어떤 순서로 짜여 있는지, 그리고 이 앱의 간판 장면인 카드 뒤집기가 자바스크립트 한 줄 없이 어떻게 도는지 그때 확인한다.
다음 장에서는 화면의 언어를 잠시 내려놓고, 이 앱의 서버 언어인 Go를 같은 방식의 작은 예제로 익혀 보자.
