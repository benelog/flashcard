= 개발 도구 설치와 첫 실행: 깔고, 받고, 띄운다

{ch-requirements~instructing}은 아무것도 설치하지 않고 읽기만 하는 장이었다.
이 장부터 손을 움직인다.
Git, Go, sqlite3를 설치하고, Flashcard의 완성된 저장소를 클론해 내 컴퓨터에서 띄운 뒤, 화면 뒤에서 데이터가 파일 하나에 쌓이는 것까지 확인한다.
이렇게 손에 쥔 앱을 2부에서는 이루는 언어의 문법부터 익히고, 3부에서는 코드로 해부한다.

이미 도구를 갖춘 독자라면 "한 번에 확인하기" 절에서 버전만 확인하고 클론으로 건너뛰어도 된다.
설치 절차는 도구가 개정되며 달라질 수 있으므로, 여기 적힌 방법이 막히면 각 공식 사이트의 안내를 우선하자.

모든 설치와 확인 명령은 터미널에 입력한다.

.[용어 풀이] 터미널(Terminal)
[NOTE]
====
마우스 대신 키보드로 명령을 입력해 컴퓨터를 조작하는 문자 기반 창이다.
macOS에는 "터미널", 윈도우에는 PowerShell이라는 이름으로 기본 설치돼 있고, 리눅스 데스크톱에도 같은 이름의 앱이 있다.
이 책에 나오는 `go run ./cmd/server` 같은 명령은 모두 이 창에 입력하고 엔터를 쳐서 실행한다.
====

macOS는 ⌘+스페이스를 눌러 "터미널"을 검색해 실행하고, 윈도우는 시작 메뉴에서 "PowerShell"을 검색해 실행하며, 우분투 리눅스는 Ctrl+Alt+T를 누른다.
창이 뜨면 커서가 깜빡이는 자리에 명령을 한 줄 입력하고 엔터를 치면 된다.

윈도우 독자에게 권할 것이 하나 있다.
셸(shell)은 터미널 창 안에서 내가 친 명령을 알아듣고 실행해 주는 프로그램인데, 운영체제마다 종류가 달라 같은 명령이 통하지 않기도 한다.
이 책 4부와 5부에는 macOS·리눅스의 셸을 전제한 명령이 있다({ch-migrations}의 `migrate_dev.sh`, {ch-env-secrets}의 `run_dev.sh`와 `source` 명령, {ch-free-tier}의 `pg_dump` 백업 명령).
WSL(Windows Subsystem for Linux)을 켜고 그 안에서 실습하면 책의 명령을 그대로 따라 할 수 있다.
PowerShell만으로도 3부까지는 문제없으니 지금 당장 결정하지 않아도 된다.

.[용어 풀이] WSL(Windows Subsystem for Linux)
[NOTE]
====
윈도우 안에서 우분투 같은 리눅스를 함께 돌려 주는 마이크로소프트의 공식 기능이다.
윈도우 위에 리눅스 터미널 창이 하나 더 생기는 형태라, 리눅스·macOS 셸을 전제로 쓰인 설치 안내와 문서의 명령을 그대로 실행할 수 있다.
PowerShell을 관리자 권한으로 열어(시작 메뉴에서 PowerShell을 오른쪽 클릭 → "관리자 권한으로 실행") `wsl --install`을 한 번 실행하고 컴퓨터를 다시 시작하면 준비가 끝난다.
====

== 무엇이 언제 필요한가

각 도구가 처음 쓰이는 자리는 다음과 같다(지금 다 설치해 두기를 권한다).

|===
| 도구 | 처음 쓰는 곳 | 용도

| Git | 이 장 | 저장소를 내 컴퓨터로 복사(클론)
| Go | 이 장 | 앱 서버 실행
| sqlite3 | 이 장 | 데이터베이스 파일 열어 보기, {ch-database-basics}의 SQL 실습
| VS Code(선택) | {ch-local-dev} | 코드 편집기
| pg_dump(선택) | {ch-free-tier} | 운영 데이터베이스 백업
|===

4부에서 필요해지는 GitHub·Vercel·Supabase는 설치할 프로그램이 아니라 가입할 서비스이므로 그때그때 안내한다.

== 설치 방법을 고르는 기준

설치 방법은 두 갈래다.
공식 사이트에서 설치 파일을 내려받아 실행하는 방법과, 패키지 매니저로 명령 한 줄에 설치하는 방법이다.

.[용어 풀이] 패키지 매니저(Package Manager)
[NOTE]
====
프로그램의 내려받기, 설치, 업그레이드를 명령 한 줄로 처리해 주는 도구다.
휴대폰의 앱 스토어를 명령줄로 옮겨 놓은 셈이다.
macOS의 Homebrew, 윈도우의 winget, 우분투 리눅스의 apt가 대표적이다.
====

공식 설치 파일은 항상 최신 버전을 주고, 패키지 매니저는 여러 도구를 한꺼번에 업그레이드할 수 있어 편하지만 등록된 버전이 늦을 수 있다.
특히 우분투 기본 저장소의 Go가 늦다(이 글을 쓰는 시점의 24.04 저장소는 1.22인데 이 앱의 `go.mod`는 1.26을 요구한다).
윈도우의 winget은 윈도우 11과 윈도우 10(2018년의 1809 업데이트 이후)에 기본 내장돼 있고footnote:[https://learn.microsoft.com/en-us/windows/package-manager/winget/[Microsoft Learn의 WinGet 문서] 기준으로, 윈도우 10은 버전 1809(빌드 17763) 이상에서 지원된다.], macOS의 Homebrew는 brew.sh의 안내를 따라 먼저 설치해야 한다.
아래에서는 두 방법을 함께 적어 두겠다.

== Git

Git은 코드의 변경 이력을 관리하는 버전 관리 도구다({ch-git}).
이 장에서는 저장소를 내 컴퓨터로 복사하는 클론(clone)에 쓴다.

* *macOS*: 터미널에서 `git`을 처음 실행하면 명령줄 개발자 도구를 설치하겠느냐는 창이 뜨는데, 설치를 누르면 Git이 함께 들어온다. Homebrew를 쓴다면 `brew install git`으로도 된다.
* *윈도우*: `winget install --id Git.Git`을 실행하거나, git-scm.com에서 Git for Windows 설치 파일을 내려받아 실행한다.
* *우분투 리눅스*: `sudo apt install git`을 실행한다.

.[용어 풀이] sudo(관리자 권한 실행)
[NOTE]
====
명령 앞에 붙여 그 명령 하나만 관리자 권한으로 실행하게 하는 리눅스·macOS의 명령이다.
프로그램을 시스템 폴더에 설치하는 일처럼 컴퓨터 전체에 영향을 주는 작업에 필요하다.
실행하면 로그인 비밀번호를 물어보는데, 입력해도 화면에는 아무 글자도 나타나지 않으니 그대로 치고 엔터를 누르면 된다.
윈도우에서 이에 해당하는 것은 "관리자 권한으로 실행"으로 연 PowerShell 창이다.
====

설치가 끝났으면 커밋 이력에 남을 이름과 이메일을 전역 설정에 등록해 둔다({ch-git}에서 커밋을 만들 때 필요하다).

[source,bash]
----
git config --global user.name "이름"
git config --global user.email "이메일 주소"
----

따옴표 안의 값을 자기 이름과 이메일로 바꿔 실행한다(GitHub 계정에 쓸 이메일과 같은 주소가 좋다).

== Go

Go는 이 앱을 만드는 언어다.
공식 다운로드 페이지(go.dev/dl)가 macOS·윈도우·리눅스용 설치 파일을 모두 제공한다.

* *macOS*: go.dev/dl의 설치 파일을 실행하거나, `brew install go`를 실행한다.
* *윈도우*: `winget install --id GoLang.Go`를 실행하거나, go.dev/dl의 설치 파일을 실행한다.
* *우분투 리눅스*: 기본 저장소의 버전이 늦으므로 go.dev/dl에서 압축 파일을 받아 직접 푸는 방법을 권한다. 두 단계가 필요하다.

먼저 터미널에서 내려받은 파일이 있는 폴더로 이동한 뒤(브라우저로 받았다면 보통 `cd ~/다운로드` 또는 `cd ~/Downloads`), 받은 파일을 `/usr/local`에 푼다(파일 이름의 버전은 내려받은 것에 맞춰 바꾼다).

[source,bash]
----
sudo tar -C /usr/local -xzf go1.26.0.linux-amd64.tar.gz
----

그다음 푼 폴더를 터미널이 명령을 찾아다니는 목록에 등록해야 `go` 명령이 동작한다.

[source,bash]
----
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
----

이 한 줄을 넣고 터미널을 닫았다 다시 열면 `go` 명령이 어디서든 실행된다.

.[용어 풀이] PATH와 셸 설정 파일
[NOTE]
====
PATH는 터미널이 명령을 찾아다니는 폴더 목록이고, 목록에 없는 프로그램은 설치돼 있어도 "명령을 찾을 수 없다"는 오류가 난다.
목록에 폴더를 더하려면 터미널을 열 때마다 자동으로 실행되는 셸 설정 파일에 위와 같은 한 줄을 추가하고 터미널을 다시 연다.
그 파일은 홈 폴더의 `~/.bashrc`(bash) 또는 `~/.zshrc`(zsh)이고, 지금 쓰는 셸은 `echo $SHELL`로 확인할 수 있다(zsh라면 위 명령의 `~/.bashrc`를 `~/.zshrc`로 바꾼다).
====

패키지 매니저로 설치한 버전이 조금 뒤처져도 걱정할 일은 아니다.
Go 프로젝트에는 어떤 Go 버전으로 만든 코드인지 적어 둔 `go.mod` 파일이 들어 있고, Go 1.21부터는 이 파일이 더 새 버전을 요구하면 그 버전의 툴체인을 자동으로 내려받아 쓴다.
이 앱의 `go.mod`는 1.26.4를 적어 두었으므로, 1.21 이상만 설치돼 있으면 처음 빌드할 때 1.26.4 툴체인을 알아서 받아 온다.

설치를 마쳤으면 버전을 확인한다.

[source,bash]
----
go version
----

== sqlite3

sqlite3는 SQLite 데이터베이스 파일을 열어 SQL을 실행하는 명령줄 도구로, 이 장 뒤쪽과 {ch-database-basics}의 SQL 실습에서 쓴다.

* *macOS*: 기본으로 들어 있어 설치할 것이 없다.
* *윈도우*: `winget install --id SQLite.SQLite`를 실행하거나, sqlite.org의 다운로드 페이지에서 sqlite-tools 압축 파일을 받아 푼다. 압축을 푼 경우에는 그 폴더를 PATH에 추가해야 `sqlite3` 명령이 어디서든 실행된다(윈도우의 PATH는 시작 메뉴에서 "시스템 환경 변수 편집"을 검색해 나오는 화면에서 추가한다).
* *우분투 리눅스*: `sudo apt install sqlite3`를 실행한다.

설치를 마쳤으면 버전을 확인한다.

[source,bash]
----
sqlite3 --version
----

== 선택 도구: VS Code

VS Code는 없어도 책을 따라갈 수 있지만, 2부부터 예제 파일을 만들어 실행하고 3부에서 완성본의 코드 파일을 여럿 오가며 읽으려면 이 시점에 갖춰 두기를 권한다.
code.visualstudio.com에서 OS에 맞는 설치 파일을 내려받아 설치하면 된다.
이 저장소에는 권장 확장 목록(`.vscode/extensions.json`)이 들어 있어, 저장소를 열면 VS Code가 필요한 확장의 설치를 제안한다.
함수 이름을 눌러 정의로 건너뛰고, 저장하는 순간 타입 오류를 표시해 주는 기능이 어디서 나오는지는 {ch-local-dev}에서 다룬다.

== 한 번에 확인하기

설치를 마쳤다면 다음 명령들이 각각 버전을 출력하는지 확인한다.

[source,bash]
----
git --version
go version
sqlite3 --version
----

성공하면 이런 모양의 줄이 세 번 나온다.

----
git version 2.43.0
go version go1.26.0 darwin/arm64
3.45.1 2024-01-15 ...
----

버전 번호와 뒤에 붙는 정보는 컴퓨터마다 다르니 숫자가 위와 달라도 괜찮다.
참고로 이 책의 코드는 Go 1.26에서 확인했다.

명령을 찾을 수 없다는 오류가 나오면 원인은 셋 중 하나다.
아직 설치하지 않았거나, 설치 직후라 터미널을 새로 열어야 반영되거나, PATH에 설치 폴더가 등록되지 않은 것이다.
창을 닫고 다시 열어도 같으면 "PATH와 셸 설정 파일" 상자로 돌아가 확인하자.

== 클론에서 실행까지, 명령 하나

이제 앱을 받아 올 차례다.
클론 명령 한 줄로 저장소를 내려받는다(Git 자체는 {ch-git}에서 다룬다).

.[용어 풀이] 클론(Clone)
[NOTE]
====
GitHub 같은 서비스에 올라가 있는 프로젝트를 내 컴퓨터로 통째로 복사해 오는 일이다.
지금의 파일뿐 아니라 지금까지의 변경 이력까지 함께 받아 오므로, 복사가 끝난 뒤에는 인터넷이 끊겨도 과거의 기록을 열어 볼 수 있다.
받아 온 사본은 마음껏 고쳐도 원본에 영향이 없고, 망가뜨렸다면 폴더를 지우고 다시 클론하면 처음 상태로 돌아온다.
====

[source,bash]
----
git clone https://github.com/benelog/flashcard.git
cd flashcard/flashcard-advanced
----

이 저장소에는 책 원고(`book/`)와 2부에서 쓸 연습용 코드(`flashcard-basic/`, `language-basic/`)도 함께 있고, 완성본 앱은 `flashcard-advanced/` 디렉터리에 있다.

.[용어 풀이] 디렉터리와 프로젝트 루트(Directory, Project Root)
[NOTE]
====
디렉터리는 폴더의 다른 이름이다.
터미널은 늘 한 디렉터리 안에서 동작하고, `cd`로 다른 디렉터리로 옮겨 간다(위의 `cd flashcard/flashcard-advanced`가 그 예다).
프로젝트 루트는 프로젝트의 파일을 모두 담은 가장 바깥 디렉터리이고, 이 저장소에서는 클론으로 생긴 `flashcard/`다.
AI 코딩 에이전트는 실행한 디렉터리를 작업 공간으로 삼으므로 프로젝트 루트에서 실행한다.
====

쓰는 AI 코딩 에이전트도 저장소 루트인 `flashcard/`에서 실행한다.
서버는 `flashcard-advanced/` 디렉터리에서 띄운다.

[source,bash]
----
go run ./cmd/server
----

처음 한 번은 의존성을 내려받고 컴파일하느라 30초 남짓(저자의 노트북 기준) 기다리고, 두 번째부터는 1초 안에 뜬다.
서버가 뜨면 로그 한 줄이 나온다.

----
2026/07/11 06:15:20 flashcard api listening on :8080 (local mode, sqlite: local-db/flashcard.db)
----

`local mode`는 아무 설정도 주지 않아 서버가 로컬 모드로 떴고, 데이터는 `local-db/flashcard.db`라는 SQLite 파일에 저장된다는 뜻이다.
이 Go 서버 하나가 화면과 데이터 요청을 모두 처리하므로 켜 둘 프로그램도 이것 하나뿐이다(이 구조는 {ch-gin}에서 다룬다).
같은 디렉터리에는 이 명령을 감싼 `run_local.sh`도 있다.

[source,bash]
----
include::../../flashcard-advanced/run_local.sh[]
----

첫 줄은 이 파일을 bash라는 셸로 실행하라는 표시이고, `#`으로 시작하는 줄은 주석이다.
`set` 줄은 도중에 오류가 나면 곧바로 멈추라는 안전장치, `cd` 줄은 이 파일이 있는 디렉터리로 먼저 옮겨 가라는 뜻이다.
마지막 줄의 `exec`는 스크립트를 실행하던 셸 대신 서버 프로그램이 그 자리를 이어받게 하는 지시인데, 겉보기 동작은 같으니 지금은 넘어가도 된다.
`env -u DATABASE_URL`은 어느 데이터베이스에 붙을지 알려 주는 설정값 `DATABASE_URL`을 지운 채 실행하라는 뜻이다.
이 값이 셸에 남아 있으면 서버는 로컬 모드 대신 그 데이터베이스에 붙으려 하므로, 배포 환경의 값을 다루기 시작하면({ch-env-secrets}) 스크립트 쪽이 안전하다.

브라우저로 `http://localhost:8080`을 열면 로그인 화면 없이 곧바로 홈 화면이 나오고, 계정 이메일이 있을 상단 바 오른쪽 자리에는 "로컬 모드"라고 적혀 있다.
터미널 창은 열어 두어야 하며, 서버를 끌 때는 그 창에서 Ctrl+C를 누른다.

.[용어 풀이] localhost와 포트(Port)
[NOTE]
====
localhost는 "내 컴퓨터 자신"을 가리키는 주소라, 이 주소로 보낸 요청은 인터넷으로 나가지 않고 방금 켠 서버로 되돌아온다.
뒤에 붙는 8080은 포트, 곧 한 컴퓨터 안에서 여러 프로그램이 각자 나눠 갖는 창구 번호다.
다른 프로그램이 8080번을 이미 쓰고 있어 서버가 뜨지 않으면, {ch-local-dev}에서 볼 `PORT=9090`으로 번호를 바꾸면 된다.
====

"기본 영단어"라는 덱을 만들고 resilient와 deliberate 두 카드를 추가해 학습을 시작하면, {ch-requirements}에서 화면 캡처로만 봤던 흐름이 내 컴퓨터에서 돈다.
맞음과 틀림을 고를 때마다 복습 기록이 한 줄씩 테이블(`review_logs`)에 쌓이고, SRS 함수가 다음 복습 시각을 계산하며, 서버가 그 결과를 화면으로 그려 보낸다.
이 장치들은 3부에서 코드로 해부한다.

여기서 지킨 규약은 하나다.
*환경 변수가 하나도 없으면 로컬 모드다.*
환경 변수는 프로그램을 실행할 때 코드 바깥에서 건네주는 설정값({ch-instructing})이고, `DATABASE_URL`이 그런 값 하나다.
클론 직후의 저장소에는 그 값이 없으므로 서버는 로컬 모드로 동작하며, 그 원리는 {ch-local-dev}에서 파고든다.

== 내 데이터는 파일 하나에 있다

앱을 조금 만져 봤다면 `flashcard-advanced/` 아래에 `local-db/flashcard.db`가 만들어졌을 것이다(쓰는 도중에는 `-wal`·`-shm`이 붙은 작업 파일 두 개도 함께 보인다).
이 파일이 데이터베이스 전부다.
`local-db/` 디렉터리는 Git이 추적하지 않을 목록(`.gitignore`)에 올라 있어서, 내 학습 데이터가 저장소에 딸려 들어갈 일은 없다({ch-git}).

테이블을 만드는 명령을 한 번도 실행하지 않았는데도 테이블들이 전부 준비되어 있는 것은, 서버가 시작할 때 스키마(테이블의 구조 정의)를 통째로 적용하기 때문이다.
그 스키마 파일 `internal/litestore/schema.sql`은 모든 문장이 "이미 있으면 건너뛰라"(`if not exists`)는 꼴이라 몇 번을 다시 실행해도 이미 있는 테이블과 인덱스는 건드리지 않는다.
이 일을 하는 Go 코드는 {ch-local-dev}에서, 스키마 파일 자체는 {ch-database-design}에서 읽는다.

이번에는 데이터베이스 파일을 sqlite3로 직접 열어 보자.
서버를 잠시 멈춘 뒤(Ctrl+C) `flashcard-advanced/` 디렉터리에서 `sqlite3 local-db/flashcard.db`를 실행한다.

화면에 뜨는 `sqlite>`는 도구가 명령을 기다린다는 입력 대기 표시이고, 아래 블록에서 그 뒤에 이어지는 부분만 입력한 것이다.
`.tables`처럼 점으로 시작하는 명령은 SQL이 아니라 sqlite3 도구 자체에 내리는 지시이며, 빠져나올 때는 `.quit`을 입력한다.

----
sqlite> .tables
card_srs          cards_with_stats  profiles          smart_decks
cards             decks             review_logs       study_sessions
sqlite> select name from decks;
기본 영단어
sqlite> select text, meaning from cards;
resilient|회복력 있는
deliberate|의도적인; 심사숙고하다
----

브라우저에서 만든 덱과 카드가 테이블 형태로 그대로 들어 있다.
방금 입력한 `select`가 데이터베이스에 묻는 언어인 SQL이고, {ch-database-basics}에서 바로 이 파일을 상대로 SQL을 익힌다.
`.tables` 목록의 `cards_with_stats`는 테이블이 아니라 통계 조회용 뷰(view)다({ch-database-design}).
`profiles`의 사용자 한 명은 로그인 없는 로컬 모드에서 모든 데이터의 주인이 되는 고정 사용자다({ch-local-dev}).
실수로 망가뜨려도 파일을 지우고 서버를 다시 켜면 빈 상태에서 새로 시작하므로, SQL을 실험할 놀이터로 이 파일만 한 것이 없다.

백업도 서버를 멈춘 상태에서 파일을 복사하면 끝이다.
sqlite3로 한 번 열었다 닫으면 작업 파일의 내용이 본 파일로 합쳐지므로 `local-db/flashcard.db` 하나만 복사해도 된다.
운영 데이터베이스에서는 파일 복사가 통하지 않으므로, 그 백업은 {ch-free-tier}에서 다룬다.

== 정리

* 필수 도구는 저장소를 복사해 오는 Git, 앱 서버를 돌리는 Go, 데이터베이스 파일을 열어 보는 sqlite3 셋이다. 공식 설치 파일과 패키지 매니저 중 어느 쪽이든 좋지만, 우분투 기본 저장소의 Go처럼 버전이 뒤처진 경우만 주의한다.
* AI 코딩 에이전트는 실행한 디렉터리를 작업 공간으로 삼으므로 저장소 루트에서 실행한다.
* 앱은 `go run ./cmd/server` 한 줄로 로컬 모드로 떠서 로그인 없이 홈 화면까지 열렸다. 환경 변수가 하나도 없으면 로컬 모드라는 규약 덕분이다.
* 데이터는 `local-db/flashcard.db`라는 SQLite 파일 하나에 쌓이고, sqlite3로 그 파일을 열어 방금 만든 덱과 카드를 확인했다.

다음 {ch-html-hello}부터는 방금 만진 화면이 무엇으로 만들어졌는지, 브라우저가 표시하는 문서의 언어인 HTML을 파일 하나짜리 연습 예제로 첫걸음부터 익힌다.
