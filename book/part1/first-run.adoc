= 개발 도구 설치와 첫 실행: 깔고, 받고, 띄운다

여기까지 오는 동안 독자가 컴퓨터에 설치한 것은 하나도 없다.
{ch-requirements}에서는 만들 앱이 해 줘야 할 일을 정했고, {ch-tech-choices}에서는 제약에서 기술이 도출되는 과정을 따졌고, {ch-claude-code}에서는 AI 코딩 에이전트가 무엇을 잘하고 어디서 틀리는지 읽었고, {ch-instructing}에서는 그 에이전트에게 지시해 골격을 얻는 과정을 대화 예시로 좇았다.
코드가 나올 때마다 눈으로 읽고 왜 그렇게 되는지 이해했을 뿐, 아직 아무것도 돌려 보지 않았다.
읽기만 해도 따라올 수 있게 일부러 그렇게 짰다.

이 장부터 손을 움직인다.
먼저 Git, Go, sqlite3를 설치하고, 이어서 이 책이 처음부터 끝까지 소재로 삼는 Flashcard의 완성된 저장소를 클론해 내 컴퓨터에서 띄운다.
{ch-instructing}에서 만든 것이 골격이었다면, 여기서 손에 넣는 것은 완성본이다.
덱을 만들고 카드를 뒤집는 화면 뒤에서 데이터가 파일 하나에 쌓이는 것도 직접 확인한다.
이렇게 손에 쥔 앱이 이 책의 나머지를 받치는 실물이다.
2부에서는 이 앱을 이루는 세 언어의 문법을 첫걸음부터 익히고, 3부에서는 같은 앱을 코드로 해부한다.

이미 도구를 갖춘 독자라면 "한 번에 확인하기" 절에서 버전만 확인하고 클론으로 건너뛰어도 된다.
설치 절차와 명령은 도구가 개정되며 달라질 수 있으므로, 여기 적힌 방법이 막히면 각 공식 사이트의 안내를 우선하자.

모든 설치와 확인 명령은 터미널에 입력한다.

.[용어 풀이] 터미널(Terminal)
[NOTE]
====
마우스 대신 키보드로 명령을 입력해 컴퓨터를 조작하는 문자 기반 창이다.
macOS에는 "터미널", 윈도우에는 PowerShell이라는 이름으로 기본 설치돼 있고, 리눅스 데스크톱에도 같은 이름의 앱이 있다.
이 책에 나오는 `go run ./cmd/server` 같은 명령은 모두 이 창에 입력하고 엔터를 쳐서 실행한다.
====

여는 법은 이렇다.
macOS는 ⌘+스페이스를 눌러 "터미널"을 검색해 실행하고, 윈도우는 시작 메뉴에서 "PowerShell"을 검색해 실행하며, 우분투 리눅스는 Ctrl+Alt+T를 누른다.
창이 뜨면 커서가 깜빡이는 자리에 명령을 한 줄 입력하고 엔터를 치면 된다.

윈도우 독자에게는 한 가지 권하고 싶은 것이 있다.
셸(shell)은 터미널 창 안에서 내가 친 명령을 알아듣고 실행해 주는 프로그램인데, 운영체제마다 종류가 달라 같은 명령이 통하지 않기도 한다.
이 책 4부와 5부에는 macOS·리눅스의 셸을 전제한 명령이 몇 개 있으므로({ch-env-secrets}의 실행 스크립트, {ch-free-tier}의 백업 명령 등), WSL(Windows Subsystem for Linux)을 켜고 그 안에서 실습하면 책의 명령을 그대로 따라 할 수 있다.
WSL 없이 PowerShell만으로도 3부까지는 문제없이 진행되니, 지금 당장 결정하지 않아도 된다.

.[용어 풀이] WSL(Windows Subsystem for Linux)
[NOTE]
====
윈도우 안에서 우분투 같은 리눅스를 함께 돌려 주는 윈도우의 공식 기능이다.
가상 머신을 따로 준비하지 않아도 윈도우 위에 리눅스 터미널 창이 하나 더 생기는 형태이고, 윈도우 쪽 파일도 그 안에서 그대로 읽고 쓸 수 있다.
개발 도구의 설치 안내와 오픈소스 문서는 대부분 리눅스·macOS의 셸을 전제로 쓰여 있어서, WSL을 켜 두면 그런 명령을 윈도우용으로 옮겨 적지 않고 그대로 실행할 수 있다.
PowerShell을 관리자 권한으로 열어(시작 메뉴에서 PowerShell을 찾아 오른쪽 클릭 → "관리자 권한으로 실행") `wsl --install`을 한 번 실행하고 컴퓨터를 다시 시작하면 준비가 끝난다.
====

== 무엇이 언제 필요한가

책 전체에서 각 도구가 처음 쓰이는 자리를 먼저 짚어 두겠다.
지금 다 설치해 두면 이후 장에서 실습이 멈출 일이 없고, 급하다면 아래 표를 보고 필요한 시점에 이 장으로 돌아와 설치해도 된다.

|===
| 도구 | 처음 쓰는 곳 | 용도

| Git | 이 장 | 저장소를 내 컴퓨터로 복사(클론)
| Go | 이 장 | 앱 서버 실행
| sqlite3 | 이 장 | 데이터베이스 파일 열어 보기, {ch-database-basics}의 SQL 실습
| Claude Code(선택) | 이 장 | {ch-claude-code}에서 읽은 AI 코딩 에이전트
| VS Code(선택) | {ch-local-dev} | 코드 편집기
| pg_dump(선택) | {ch-free-tier} | 운영 데이터베이스 백업
|===

4부에서 필요해지는 GitHub·Vercel·Supabase는 설치할 프로그램이 아니라 가입할 서비스이므로, 각 장에서 그때그때 안내한다.

== 설치 방법을 고르는 기준

설치 방법은 크게 두 갈래다.
공식 사이트에서 설치 파일을 내려받아 실행하는 방법과, 패키지 매니저로 명령 한 줄에 설치하는 방법이다.

.[용어 풀이] 패키지 매니저(Package Manager)
[NOTE]
====
프로그램의 내려받기, 설치, 업그레이드를 명령 한 줄로 처리해 주는 도구다.
휴대폰의 앱 스토어를 명령줄로 옮겨 놓은 셈이다.
macOS의 Homebrew, 윈도우의 winget, 우분투 리눅스의 apt가 대표적이다.
====

공식 설치 파일은 어느 컴퓨터에서나 절차가 같고 항상 최신 버전을 준다.
패키지 매니저는 설치가 명령 한 줄로 끝나고 나중에 여러 도구를 한꺼번에 업그레이드할 수 있어 편하지만, 저장소에 따라 등록된 버전이 공식 최신보다 늦을 수 있다.
특히 우분투 기본 저장소의 Go는 최신에서 몇 단계 뒤처진 버전인 경우가 많아 아래에서 따로 짚는다.
윈도우의 winget은 윈도우 11과 최신 윈도우 10에 기본 내장돼 있고, macOS의 Homebrew는 기본 내장이 아니므로 쓰려면 brew.sh의 안내를 따라 먼저 설치해야 한다.
둘 중 무엇을 골라도 결과는 같으니, 아래에서는 두 방법을 함께 적어 두겠다.

== Git

Git은 코드의 변경 이력을 관리하는 버전 관리 도구다.
개념은 {ch-git}에서 다루지만, 저장소를 내 컴퓨터로 복사하는 클론(clone)에 쓰이므로 이 장 뒤쪽의 실습 전에 설치가 필요하다.

* *macOS*: 터미널에서 `git`을 처음 실행하면 명령줄 개발자 도구를 설치하겠느냐는 창이 뜨는데, 설치를 누르면 Git이 함께 들어온다. Homebrew를 쓴다면 `brew install git`으로도 된다.
* *윈도우*: `winget install --id Git.Git`을 실행하거나, git-scm.com에서 Git for Windows 설치 파일을 내려받아 실행한다.
* *우분투 리눅스*: `sudo apt install git`을 실행한다.

.[용어 풀이] sudo(관리자 권한 실행)
[NOTE]
====
명령 앞에 붙여 그 명령 하나만 관리자 권한으로 실행하게 하는 리눅스·macOS의 명령이다.
프로그램을 시스템 폴더에 설치하는 일처럼 컴퓨터 전체에 영향을 주는 작업은 평소 사용자 권한으로 막혀 있어서 이 명령이 필요하다.
실행하면 컴퓨터 로그인 비밀번호를 물어보는데, 보안을 위해 입력해도 화면에는 아무 글자도 나타나지 않는다.
커서가 멈춰 있는 것처럼 보여도 입력은 들어가고 있으니, 당황하지 말고 그대로 치고 엔터를 누르면 된다.
윈도우에서 이에 해당하는 것은 "관리자 권한으로 실행"으로 연 PowerShell 창이다.
====

설치가 끝났으면 커밋 이력에 남을 이름과 이메일을 등록해 둔다.
다음 두 명령은 그 값을 전역 설정에 저장하는 것으로, {ch-git}에서 커밋을 만들 때 필요하다.

[source,bash]
----
git config --global user.name "이름"
git config --global user.email "이메일 주소"
----

따옴표 안의 두 값만 자기 이름과 이메일로 바꿔 실행하면 된다.
GitHub 계정을 만들 예정이라면 계정에 쓸 이메일과 같은 주소를 적어 두는 편이 좋다.

== Go

Go는 이 앱을 만드는 언어다.
공식 다운로드 페이지(go.dev/dl)가 macOS·윈도우·리눅스용 설치 파일을 모두 제공하므로, 어느 OS든 이 방법이 가장 확실하다.

* *macOS*: go.dev/dl의 설치 파일을 실행하거나, `brew install go`를 실행한다.
* *윈도우*: `winget install --id GoLang.Go`를 실행하거나, go.dev/dl의 설치 파일을 실행한다.
* *우분투 리눅스*: 기본 저장소의 버전이 몇 단계 뒤처진 경우가 많으므로 go.dev/dl에서 압축 파일을 받아 직접 푸는 방법을 권한다. 설치 파일을 실행하는 macOS·윈도우와 달리 두 단계가 필요하다.

리눅스에서 압축 파일로 설치할 때는 먼저 터미널에서 내려받은 파일이 있는 폴더로 이동한다(브라우저로 받았다면 보통 `cd ~/다운로드` 또는 `cd ~/Downloads`).
그다음 받은 파일을 `/usr/local`에 푼다(파일 이름의 버전은 내려받은 것에 맞춰 바꾼다).

[source,bash]
----
sudo tar -C /usr/local -xzf go1.26.0.linux-amd64.tar.gz
----

여기까지 해도 `go` 명령은 아직 동작하지 않는다.
푼 폴더를 터미널이 명령을 찾아다니는 목록에 등록해야 한다.

[source,bash]
----
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
----

이 한 줄을 넣고 터미널을 닫았다 다시 열면 `go` 명령이 어디서든 실행된다.

.[용어 풀이] PATH와 셸 설정 파일
[NOTE]
====
PATH는 터미널이 명령을 찾아다니는 폴더 목록이다.
`go`라고만 쳐도 실행되는 것은 Go가 설치된 폴더가 이 목록에 들어 있기 때문이고, 목록에 없으면 프로그램이 설치돼 있어도 "명령을 찾을 수 없다"는 오류가 난다.
목록에 폴더를 더하려면 터미널을 열 때마다 자동으로 실행되는 셸 설정 파일에 위와 같은 한 줄을 추가하고 터미널을 다시 연다.
그 파일은 홈 폴더의 `~/.bashrc`(bash) 또는 `~/.zshrc`(zsh)이고, 지금 쓰는 셸이 무엇인지는 `echo $SHELL`로 확인할 수 있다(zsh를 쓴다면 위 명령의 `~/.bashrc`를 `~/.zshrc`로 바꾼다).
====

패키지 매니저로 설치한 버전이 최신에서 조금 뒤처져도 크게 걱정할 일은 아니다.
Go 프로젝트에는 어떤 Go 버전으로 만든 코드인지 적어 둔 `go.mod`라는 파일이 함께 들어 있다.
Go 1.21부터는 이 파일이 설치된 것보다 새 버전을 요구하면, 설치된 Go가 그 버전의 도구 일습(툴체인)을 자동으로 내려받아 사용한다.

설치를 마쳤으면 버전을 확인한다.

[source,bash]
----
go version
----

== sqlite3

sqlite3는 SQLite 데이터베이스 파일을 열어 SQL을 실행하는 명령줄 도구로, 이 장 뒤쪽에서 로컬 데이터베이스 파일을 들여다볼 때와 {ch-database-basics}에서 SQL을 실습할 때 쓴다.

* *macOS*: 기본으로 들어 있어 설치할 것이 없다.
* *윈도우*: `winget install --id SQLite.SQLite`를 실행하거나, sqlite.org의 다운로드 페이지에서 sqlite-tools 압축 파일을 받아 푼다. 압축을 푼 경우에는 그 폴더에서 터미널을 열거나, 앞의 Go 절에서 본 PATH에 그 폴더를 추가해야 `sqlite3` 명령이 어디서든 실행된다(윈도우의 PATH는 셸 설정 파일이 아니라 시작 메뉴에서 "시스템 환경 변수 편집"을 검색해 나오는 화면에서 추가한다).
* *우분투 리눅스*: `sudo apt install sqlite3`를 실행한다.

설치를 마쳤으면 버전을 확인한다.

[source,bash]
----
sqlite3 --version
----

== 선택 도구: VS Code와 Claude Code

다음 두 도구는 없어도 책을 따라갈 수 있지만, 있으면 {ch-claude-code·instructing}에서 읽기만 했던 이야기와 {ch-local-dev}의 개발 환경을 직접 체험할 수 있다.

VS Code는 code.visualstudio.com에서 OS에 맞는 설치 파일을 내려받아 설치한다.
이 저장소에는 권장 확장 목록(`.vscode/extensions.json`)이 들어 있어, 저장소를 열면 VS Code가 필요한 확장의 설치를 알아서 제안한다.
2부부터는 예제 파일을 직접 만들어 실행하고 3부에서는 완성본의 코드 파일을 여럿 오가며 읽게 되므로, 편집기는 이 시점에 갖춰 두기를 권한다.
함수 이름을 눌러 정의로 건너뛰고 타입 오류를 저장하는 순간 표시해 주는 기능이 코드를 읽는 속도를 크게 바꾸기 때문이다.
그 기능들이 어떤 파일 설정에서 나오는지는 {ch-local-dev}에서 해부하지만, 지금은 설치해 두고 쓰기만 해도 된다.

Claude Code는 {ch-claude-code}에서 다룬 AI 코딩 에이전트다.
공식 가이드가 권장하는 방법은 OS별 설치 스크립트 실행이다.

macOS·리눅스(앞서 본 WSL 포함)는 터미널에서 다음 명령을 실행한다.
설치 스크립트를 내려받아 바로 실행하는 명령이다.

[source,bash]
----
curl -fsSL https://claude.ai/install.sh | bash
----

윈도우는 PowerShell에서 다음 명령을 실행한다.

[source,powershell]
----
irm https://claude.ai/install.ps1 | iex
----

패키지 매니저를 쓴다면 macOS는 `brew install --cask claude-code`, 윈도우는 `winget install Anthropic.ClaudeCode`로도 설치할 수 있다.
다만 설치 스크립트 쪽은 이후 새 버전이 자동으로 반영되는 반면, 패키지 매니저 쪽은 업그레이드 명령을 직접 실행해야 한다.

설치 후 터미널에서 `claude`를 실행하면 로그인 안내가 나온다.
이용에는 Anthropic 계정이 필요하고, 유료 구독이나 API 사용량 과금 중 한 가지 방식으로 요금이 발생한다는 점은 미리 알아 두자.

== 한 번에 확인하기

설치를 마쳤다면, 다음 명령들이 각각 버전을 출력하는지 확인한다.

[source,bash]
----
git --version
go version
sqlite3 --version
----

성공하면 이런 모양의 줄이 세 번 나온다.

----
git version 2.43.0
go version go1.26.0 darwin/arm64
3.45.1 2024-01-15 ...
----

버전 번호와 뒤에 붙는 정보는 컴퓨터마다 다르니, 숫자가 위와 달라도 걱정할 것 없다.
세 명령 모두 이렇게 버전을 출력하면 이 책의 모든 실습을 진행할 준비가 끝난 것이다.

명령을 찾을 수 없다는 오류가 나오면 원인은 셋 중 하나다.
아직 설치하지 않았거나, 설치 직후라 터미널을 새로 열어야 반영되거나, PATH에 설치 폴더가 등록되지 않은 것이다.
먼저 창을 닫고 다시 열어 보고, 그래도 같은 오류가 나면 앞의 "PATH와 셸 설정 파일" 상자로 돌아가 설치한 폴더가 PATH에 들어 있는지 확인하자.
참고로 이 책의 코드는 Go 1.26에서 확인했다.

== 클론에서 실행까지, 명령 하나

도구가 준비됐으니 이제 앱을 받아 올 차례다.
저장소를 아직 받지 않았다면 클론(clone) 명령 한 줄로 내려받는다.
Git 자체는 {ch-git}에서 제대로 다루므로, 여기서는 이 명령 하나만 쓰고 지나간다.

.[용어 풀이] 클론(Clone)
[NOTE]
====
GitHub 같은 서비스에 올라가 있는 프로젝트를 내 컴퓨터로 통째로 복사해 오는 일이다.
지금의 파일들만 내려받는 것이 아니라 그 프로젝트가 지금까지 거쳐 온 변경 이력까지 함께 받아 오므로, 복사가 끝난 뒤에는 인터넷이 끊겨도 과거의 기록을 열어 볼 수 있다.
받아 온 사본은 내 것이라 마음껏 고치고 실험해도 원본에는 아무 영향이 없고, 망가뜨렸다면 폴더를 지우고 다시 클론하면 처음 상태로 돌아온다.
복사해 오는 그 꾸러미가 정확히 무엇이고 고친 결과를 어떻게 원본으로 돌려보내는지는 {ch-git}에서 다룬다.
====

[source,bash]
----
git clone https://github.com/benelog/flashcard.git
cd flashcard/flashcard-advanced
----

이 저장소에는 책 원고(`book/`)와 2부에서 쓸 연습용 코드(`flashcard-basic/`, `language-basic/`)도 함께 있는데, 완성본 앱은 `flashcard-advanced/` 디렉터리에 있다.
이제 그 디렉터리에서 서버를 띄운다.

[source,bash]
----
go run ./cmd/server
----

처음 한 번은 의존성 다운로드와 컴파일 때문에 시간이 조금 걸리고, 기동에 성공하면 로그 한 줄이 나온다.

----
2026/07/11 06:15:20 flashcard api listening on :8080 (local mode, sqlite: local-db/flashcard.db)
----

`local mode`라는 표시를 눈여겨보자.
아무 설정도 주지 않았으므로 서버가 로컬 모드로 떴고, 데이터는 `local-db/flashcard.db`라는 SQLite 파일에 저장된다는 뜻이다.
이것으로 실행은 끝이다.
이 Go 서버 하나가 화면과 데이터 요청을 모두 처리하므로, 켜 둘 프로그램이 이것 하나뿐이다.
화면 담당 서버와 데이터 담당 서버를 따로 만드는 방식이라면 창을 두 개 열어 프로그램 둘을 함께 띄워야 하는데, 여기서는 그럴 일이 없다(이 구조는 {ch-gin}에서 다룬다).
같은 디렉터리에는 이 명령을 감싼 `run_local.sh`도 있다.

[source,bash]
----
include::../../flashcard-advanced/run_local.sh[]
----

스크립트의 첫 줄은 도중에 오류가 나면 곧바로 멈추라는 안전장치이고, 둘째 줄은 어느 폴더에서 실행하든 이 파일이 있는 폴더로 먼저 옮겨 가라는 뜻이다.
서버를 띄우는 마지막 줄에서 방금 친 명령과 다른 곳은 `env -u DATABASE_URL` 하나다.
`DATABASE_URL`은 어느 데이터베이스에 붙을지 알려 주는 설정값인데, 이 값이 셸에 남아 있으면 서버는 로컬 모드 대신 그 데이터베이스로 붙으려 한다.
스크립트는 그 값을 지운 채 실행하므로 언제나 SQLite로 뜬다.
아직 그 값을 설정한 적이 없으니 지금은 어느 쪽을 써도 결과가 같고, 배포 환경의 값을 다루기 시작하면({ch-env-secrets}) 스크립트 쪽이 안전해진다.

브라우저로 `http://localhost:8080`을 열면 로그인 화면 없이 곧바로 홈 화면이 나온다.
배포된 앱이라면 계정 이메일이 있을 상단 바 오른쪽 자리에는 "로컬 모드"라고 적혀 있다.
터미널 창은 닫지 말고 그대로 열어 두어야 하며, 서버를 끌 때는 그 창에서 Ctrl+C를 누른다.

.[용어 풀이] localhost와 포트(Port)
[NOTE]
====
localhost는 "내 컴퓨터 자신"을 가리키는 주소다.
이 주소로 보낸 요청은 인터넷으로 나가지 않고 방금 내가 켠 서버로 되돌아오므로, 아직 아무에게도 공개하지 않은 앱을 내 브라우저로 열어 볼 수 있다.
뒤에 붙는 8080은 포트로, 한 컴퓨터 안에서 여러 프로그램이 각자 다른 창구 번호를 나눠 갖는 것과 같다.
다른 프로그램이 8080번 창구를 이미 쓰고 있어 서버가 뜨지 않으면, {ch-local-dev}에서 볼 `PORT=9090`으로 창구 번호를 바꿔 주면 된다.
====

"기본 영단어"라는 덱을 만들고 resilient와 deliberate 두 카드를 추가해 학습을 시작하면, {ch-requirements}에서 화면 캡처로만 봤던 그 흐름이 내 컴퓨터에서 돈다.
맞음과 틀림을 고를 때마다 복습 기록이 테이블에 쌓이고, SRS 함수가 다음 복습 시각을 계산하며, 서버가 그 결과를 화면으로 그려 보낸다.
이 장치들은 3부에서 하나씩 코드로 해부한다(테이블 설계는 {ch-database-design}, SRS 함수는 {ch-core-logic}, 화면 템플릿과 htmx는 {ch-html-template}과 {ch-htmx}).

여기서 지킨 규약은 하나다.
*환경 변수가 하나도 없으면 로컬 모드다.*
환경 변수는 프로그램을 실행할 때 코드 바깥에서 건네주는 설정값을 말한다.
방금 본 `DATABASE_URL`이 그런 값 하나이고, 서버는 이 값이 건네지지 않으면 로컬 모드로 동작하는데 클론 직후의 저장소에는 그 값이 없다.
설정 없이 실행되는 이 구조가 어떤 원리로 성립하는지는 {ch-local-dev}에서 파고든다.


== 내 데이터는 파일 하나에 있다

앱을 조금 만져 봤다면 `flashcard-advanced/` 아래에 `local-db/` 폴더가 생기고 그 안에 `flashcard.db`가 만들어졌을 것이다(쓰는 도중에는 `-wal`·`-shm`이 붙은 작업 파일 두 개도 함께 보인다).
이 파일이 데이터베이스 전부다.
{ch-tech-choices}에서 SQLite를 "파일 하나로 동작하는 관계형 데이터베이스"라고 소개했는데, 그 파일이 바로 이것이다.
`local-db/` 폴더는 Git이 아예 추적하지 않을 목록(`.gitignore`)에 통째로 올라 있어서, 내 학습 데이터가 저장소에 딸려 들어갈 일은 없다.
그 목록이 무엇이고 코드의 이력을 어떻게 남기는지는 {ch-git}에서 다룬다.

그런데 테이블을 만드는 명령을 한 번도 실행하지 않았는데도 이 앱의 테이블들이 전부 준비되어 있다.
서버가 시작할 때 스키마(테이블의 구조 정의)를 통째로 적용하기 때문이다.
`internal/litestore/schema.sql`이 그 스키마 파일인데, 모든 문장이 "이미 있으면 건너뛰라"(`if not exists`)는 꼴이라 몇 번을 다시 실행해도 이미 있는 테이블과 인덱스는 건드리지 않는다.
그래서 별도의 명령 없이 서버를 켜기만 하면 스키마가 준비된다.
이 일을 하는 Go 코드는 {ch-local-dev}에서 읽고, 스키마 파일 자체는 {ch-database-design}에서 발췌해 읽는다.

이번에는 데이터베이스 파일을 직접 열어 보자.
앞에서 설치한 sqlite3 명령줄 도구를 쓴다.
서버를 잠시 멈춘 뒤(Ctrl+C) `flashcard-advanced/` 디렉터리에서 `sqlite3 local-db/flashcard.db`를 실행한다.

그러면 화면에 `sqlite>`가 뜨는데, 이것은 내가 타이핑하는 글자가 아니라 도구가 "명령을 기다린다"고 찍어 주는 입력 대기 표시다.
아래 블록에서도 `sqlite>` 뒤에 이어지는 부분만 입력한 것이고, 나머지 줄은 도구가 출력한 결과다.
`.tables`처럼 점으로 시작하는 명령은 SQL이 아니라 sqlite3 도구 자체에 내리는 지시이며, 빠져나올 때는 `.quit`을 입력한다.

----
sqlite> .tables
card_srs          cards_with_stats  profiles          smart_decks
cards             decks             review_logs       study_sessions
sqlite> select name from decks;
기본 영단어
sqlite> select text, meaning from cards;
resilient|회복력 있는
deliberate|의도적인; 심사숙고하다
----

브라우저에서 만든 덱과 카드가 표 형태로 그대로 들어 있다.
방금 입력한 `select`가 데이터베이스에 묻는 언어인 SQL이고, {ch-database-basics}에서 바로 이 파일을 상대로 SQL을 익힌다.
`.tables` 목록의 `cards_with_stats`는 테이블이 아니라 통계 조회용 뷰(view)인데, 뷰가 무엇인지는 {ch-database-design}에서 다룬다.
`profiles`에는 사용자가 단 한 명 있는데, 로그인 없는 로컬 모드에서 모든 데이터의 주인이 되는 고정 사용자다(이 사용자를 만드는 코드는 {ch-local-dev}에서 본다).
무엇을 조회하든 내 데이터라 결과를 눈으로 검증할 수 있고, 실수로 망가뜨려도 파일을 지우고 서버를 다시 켜면 빈 상태에서 새로 시작한다.
그래서 SQL을 실험할 놀이터로 이 파일만 한 것이 없다.

백업도 단순해서, 서버를 멈춘 상태에서 파일을 복사하면 끝이다.
sqlite3로 한 번 열었다 닫으면 작업 파일의 내용이 본 파일로 합쳐지므로 `local-db/flashcard.db` 하나만 복사해도 된다.
데이터베이스 백업이라는 말의 무게에 비하면 싱거울 정도인데, 운영 데이터베이스에서는 파일 복사가 통하지 않으므로 백업은 {ch-free-tier}에서 전용 도구와 복원 기한을 따지는 주제로 다룬다.


== 정리

이 장에서는 개발 도구를 설치하고, 완성본 저장소를 클론해 내 컴퓨터에서 전체 앱을 띄웠다.

필수 도구는 셋이다.
저장소를 복사해 오는 Git, 앱 서버를 돌리는 Go, 데이터베이스 파일을 열어 보는 sqlite3다.
설치 방법은 공식 설치 파일과 패키지 매니저 두 갈래가 있고, 우분투 기본 저장소의 Go처럼 패키지 매니저의 버전이 뒤처진 경우만 주의하면 어느 쪽을 골라도 좋다.
선택 도구인 VS Code와 Claude Code까지 갖추면 {ch-claude-code·instructing}에서 읽은 이야기를 직접 재현할 수 있다.

앱은 `go run ./cmd/server` 한 줄로 로컬 모드로 떠서 로그인 없이 홈 화면까지 열렸다.
데이터는 `local-db/flashcard.db`라는 SQLite 파일 하나에 쌓이고, sqlite3로 그 파일을 직접 열어 방금 만든 덱과 카드를 눈으로 확인했다.
환경 변수가 하나도 없으면 로컬 모드라는 규약 덕분에 설정 없이 실행이 끝났는데, 그 원리는 {ch-local-dev}에서 파고든다.

이제 읽을 수 있는 요구사항과 만질 수 있는 앱이 모두 손에 있다.
다음 {ch-html-hello}부터는 방금 만진 화면이 무엇으로 만들어졌는지부터 배운다.
브라우저가 표시하는 문서의 언어인 HTML을, 저장소가 아니라 파일 하나짜리 연습 예제로 첫걸음부터 익힌다.
